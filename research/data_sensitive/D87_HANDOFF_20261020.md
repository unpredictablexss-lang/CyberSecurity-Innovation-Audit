## Before/after reproduction and exact semantic boundary

```cpp
const std::string CERT_PASSWORD = "password";
void sample(napi_env env, napi_value obj) {
    bool present = false;
    napi_has_named_property(env, obj, CERT_PASSWORD.c_str(), &present);
}
```

The baseline creates one unresolved-escape candidate from a sensitive-looking API name
`CERT_PASSWORD.c_str`. The implementation excludes that exact argument's heuristic flow when:

- The call is exactly `napi_has_named_property` or `napi_get_named_property`, with four arguments;
  argument 2 is a zero-argument dot `c_str()` on a plain global identifier.
- A single complete C++ AST definition binds that identifier, in the same lexical namespace,
  to a global `const std::string` with literal value `"password"`.
- The definition is in the same source or a uniquely matched explicit quoted header include.
  Conventional include guards are supported; arbitrary conditional definitions are rejected.
- The caller and every selected explicitly included header used for lookup are complete.
  Local/parameter references, namespace collisions, duplicate header matches, macro aliases,
  dynamic/non-const definitions and visible same-name API bodies do not receive this exclusion.

The bound schema-key operand changes one candidate to zero. This does not classify const
values or strings as public generally. Hardcoded material of another value, dynamic password
input, unknown helper/LOGE wrapper, and set-property value positions remain candidates.

The reviewed argument role is supported by the Node-API
[has-property](https://nodejs.org/api/n-api.html#napi_has_named_property) and
[get-property](https://nodejs.org/api/n-api.html#napi_get_named_property) contracts: the UTF-8
name is the property key; `get` writes its fetched value through a separate output pointer.
The local OpenHarmony Node header independently declares these four-argument signatures at
`third_party/node/src/js_native_api.h:202-209`. Compiler/build API identity remains outside
this bounded syntax model; a reduced candidate count is not a product safety verdict.

For a bound `napi_get_named_property(..., &out)`, the output gets a password-property material
source, and later actual value use remains a candidate even when `out` has an ordinary name.
The status result does not inherit schema-key taint. Other operand flows, including a named
`&password` output, remain candidates. A destination without a supported address-of binding
retains a destination-binding obligation.
