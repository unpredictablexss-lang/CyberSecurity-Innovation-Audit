## Original false candidate and observed fix

With explicit Callback argument 0 material source, first/second initialized to zero and p bound to first:

```cpp
switch(selector){case 0:return;default:return;}
*p=(unsigned char)key[0];
HILOG_INFO(1,"%{public}u",first);
```

Every selector dispatch returns from Callback, so there is no state that reaches the following write or log. Baseline nevertheless carries a fallthrough state from its unsupported-switch may-flow scan, reporting first-log line 5 with `Callback parameter 0 -> assign first -> HILOG_INFO public operand 0`. Its Runner legacy diagnostic is `ohscanner.data.sensitive_exposure:e03de75479e544aa`. The final direct and Runner both report **zero** candidates for this fixture: no source-dependent write or sink is reachable. This is the elimination of a source-level false path, not a vulnerability fix or a measured accuracy rate.

Two other independent baseline failures are now fixed: default first with three all-return arms, and a switch initializer q with two bare-return arms. Header-scope restoration does not revive a normal successor. | Shape | Source-level path fact and tested result |
| --- | --- |
| Unique numeric case(s) + one default, one direct bare return in every arm | Complete dispatch terminates Callback; no following log |
| Missing default | Nonmatching selector bypasses arms; following real material log remains |
| One arm break, another return | The break arm leaves switch with a live state; following log remains |
| Identifier label / duplicate numeric labels | Numeric-label proof not admitted; preserve candidate/partial obligations. Duplicate labels are ill-formed C++, not a semantically proven complete AST |
| Nested case block with possible conditional break | Break can reach post-switch write/log; descendant return must not terminate the whole switch |

The matrix is inspected against the standalone C++ statements; it is not presented as a compiler proof. Target code is not run.
