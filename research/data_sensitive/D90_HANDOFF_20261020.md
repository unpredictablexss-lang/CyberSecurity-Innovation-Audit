## Concrete failure and repair

T89 identified a pre-existing loss of an explicit source at a shadowed callable:

```cpp
void Callback(const char *key, void (*CfFree)(const char *)) {
    CfFree(key);
}
```

The synthetic exact source profile marks `Callback` parameter 0 as material. The old
`fn in self.shadows` branch recorded a limitation and returned without a candidate.
The same happened for a local callable alias `auto CfFree=handler; CfFree(key);`.
Both are valid C++ call forms. Neither establishes that the runtime target frees data.

The repair emits an unresolved escape for material arguments before returning. It does
not apply a same-spelling API model to the callable. The evidence retains callee-binding,
sink-behavior and impact obligations. Ordinary literal/null arguments remain zero.
The same conservative behavior covers a locally shadowed logging API name.

Fixed complete-source snapshots show direct/Runner parameter and local-alias probes
each `0/0 -> 1/1`. Ordinary argument stays `0/0`; a visible CfFree wrapper whose terminal
free binding is unproved stays `1/1`. Dedicated tests also copy material to an independent
buffer before cleanup and verify its actual later HILOG output remains a candidate.
Three historical callable controls now expect one unresolved escape, recorded explicitly
in current tests; their original historical manifests remain unchanged.
