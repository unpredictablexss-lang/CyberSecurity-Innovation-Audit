# D28: CVE-2026-27648 Chromium Flowbuffer bounds rule

Date: 2026-10-19
Detector: ohscanner.known_disclosed_cves 0.8.0
Status: exact pre-fix and fixed component sources are detected as candidate / negative control; findings remain candidates.

## Rule evidence

The OpenHarmony April 2026 bulletin lists CVE-2026-27648 for web_webview, CVSS 8.8, in the 5.0.3, 5.1.0, and 6.0 release lines. Its linked release fixes are [chromium_src PR #7093](https://gitcode.com/openharmony-tpc/chromium_src/pull/7093), [#7110](https://gitcode.com/openharmony-tpc/chromium_src/pull/7110), and [#7108](https://gitcode.com/openharmony-tpc/chromium_src/pull/7108). See the [official bulletin](https://gitcode.com/openharmony/security/blob/master/zh/security-disclosure/2026/2026-04.md).

PR #7093 changes two bounds in nweb_handler_delegate.cc: FlowbufStrAtIndex rejects offset-plus-length beyond the shared flowbuffer data area; ProcessNativeProxyResultNewFlowbuf bounds three loops that write dataList[curIndex] by destination list size. The detector retains a candidate if either the unchecked flowbuffer range or the unbounded destination loop/write shape remains in the same source file. It emits a CWE-787 candidate and retains product-build, attacker-path, and impact obligations.

## Remediation and claim boundary

The upstream patch rejects flowbuffer entries whose offset and length exceed the shared data segment, then stops reconstruction loops before the destination vector end. This is a remediation reference; OHScanner did not author or independently validate the upstream patch. A product repair report still needs exact product source/build, caller and remote-input path, and product-version mapping.

This replay confirms that the detector recognizes an actual pre-fix component revision and distinguishes the pinned fixed component revision. It does not establish that a particular OpenHarmony product used the pre-fix source, that a remote actor can reach the code, or what impact occurs in a product. Findings remain candidate, product status remains unknown, and validated_vulnerability=0. No runtime PoC was executed.
