# D98 structured handoff: exact all-return switch termination

## Problem and reproduction

Baseline owner `27301e6d824a107cb219b84a6b4e2a6f05266ab5` merged without conflict as
`d279401b92503e38f7d5468154f43618bb41ccf5`, detector 0.21.12. T96's named gap was:

```cpp
void Callback(const char *key, int selector) {
    unsigned first = 0;
    unsigned *p = &first;
    switch (selector) {
        case 0: return;
        default: return;
    }
    *p = (unsigned char)key[0];
    HILOG_INFO(1, "%{public}u", first);
}
```

Both direct detector and Runner emitted a candidate at the log, despite every arm
returning from the function. Unsupported switch traversal scanned return syntax as
effects and then revived the incoming state as live. This is a concrete unreachable-code
overcandidate, independent of production API assumptions.

## Implementation and changed files

Implementation `b3dfd70894290c344017c33198b905c70eb51985`, detector 0.21.12 → 0.21.13.

- `src/ohscanner/detectors/data/sensitive_exposure.py`: share D97's exact dispatch
  validator between pointer joins and the new termination proof. It requires complete
  selected input and shared AST statuses, no preprocessing, identifier selector, flat
  direct case arms, unique canonical nonnegative decimal labels and exactly one default.
  The new proof additionally requires each arm to contain exactly one direct bare
  `return;`. It produces actual return `ExitState` records and no fallthrough state.
  D96 initializer declaration scope is restored on every returned exit.
- A containing function with any goto or labeled statement is rejected: a goto could
  otherwise bypass the switch and reach a later label/write/log. No general CFG is built.
- `tests/detectors/data/test_d98_switch_return_liveness.py`: seven developer methods.
- `D98_probe_switch_returns.py`: fourteen full-source archive / fresh-process source
  observations, reusing the explicit synthetic source-model worker and selected-partial
  header setup from prior developer scripts.
- `D98_VALIDATION_20261020.json`: exact source identity, hashes, full direct/Runner
  records and coverage, original spans and the closed/remaining semantic boundaries.

The change preserves D97's limited same-target break-arm join. It does not add a general
break/return merge, follow grouped-label fallthrough, or suppress effects in return expressions.

## Remaining boundaries

Grouped/fallthrough all-return and return-expression all-return inputs still expose a
conservative post-switch overcandidate; the frozen probes identify these as outside the
proof, not passing safety controls. Nested returns, numeric-label evaluation beyond D97's
exact form, general switch CFG, complex aliases, compiler type identity and runtime impact
remain unresolved. Missing/partial input never grants this new unreachable-code proof.
No arbitrary API exemption or second-layer model work was introduced.
