# 队友 D：D2 后续研究方案

日期：2026-10-17。本文是下一轮计划，除明确列为已完成的 D2 基线外，均未声称已经执行。

## 1. 研究起点与目标

D2 已完成局部退出、分支与作用域修复，71 个设计/回归控制通过；全量测试为 517 通过、11 跳过。真实固定 9 文件仍只有 3 partial、6 not_analyzed，候选为零。已有两组日志删除硬化线索，但没有真实漏洞真值、独立评估或动态复现。

下一轮目标是取得可复核的覆盖改善及可信的敏感材料到日志证据，明确检测器适用范围。候选数量增加、日志被删除或测试通过，均不能单独作为真实漏洞或有效性证明。

## 2. 分阶段安排与退出条件

| 阶段 | 工作 | 交付与通过条件 |
| --- | --- | --- |
| A：审核基线 | 队长审核 D2 草稿与最小接口需求，确定可修改范围及源码/模型标识 | 审核意见、准入决议、冻结版本；未获公共接口授权时仅继续 D 内研究 |
| B：解决实际覆盖阻塞 | 以 auth_session_key.c 为试点，区分宏、错误区域、类型依赖、格式参数映射问题 | 相同源码范围下的覆盖前后对照，每个状态变化都有事实依据；不能将私有探针结果直接升级为正式完成 |
| C：核验历史线索 | 分别研究两组日志删除前后的材料构造、日志语义及读取条件 | 每对给出支持证据、反证、未知项；允许最终仍为 unknown |
| D：有依据地扩展模型 | 仅对已核验 API/版本建立新 Source / Sink 模型 | 新模型独立版本、适用提交和语义依据，配 vulnerable/fixed/safe/unrelated/unknown 控制；不与旧 0.1.0 模型混算 |
| E：独立评估 | 冻结代码和模型后，由独立标注者或独立生成流程准备留出数据 | 标注规则、样本来源与隔离记录、覆盖分母及评估报告；现有 71 控制不算留出集 |
| F：可选隔离复现 | 有合格候选且获准使用 Docker Worker/Harness 后进行 | 固定镜像、合成材料、修复前后及安全对照、读取权限证据；条件不满足则只交付缺口说明 |
| G：审核集成 | 根据证据由队长决定 Catalog / 面板接入 | 注册范围、限制与回归记录；不自动取消 Draft 或合并 |

顺序依赖：B 依赖接口决议；D 依赖 C 的语义核验；E 必须在其评估对象冻结后进行；F 依赖候选与隔离执行条件。不可用的前置条件应保留为缺口，不补写结果。

## 3. 历史线索研究重点

第一组为 `273637945ecb7b53d5d9af3bfd4e48a40bb88252` 的父子版本，关注 `registerCapaData` 的实际内容、来源和公开日志槽位。

第二组为 `63efce3ff7f2708527eb29216decaf5fe2dc33d0` 的父子版本，关注 `crypInfo.out` 在解码与 JSON 处理后的含义，以及旧 SoftBusLog 的输出条件。

每组均核对完整 commit、父提交、tree/blob 与文件 SHA-256；若能恢复 GitCode 官方访问，再核验跨镜像身份。当前 GitCode 单个 API 的 404 不能作为提交不存在的证据。

核验至少回答：输出到底是什么材料；哪些路径能到达日志；构建和日志等级是否启用；谁能读取；删除日志是否确实消除该泄露路径。若只是设备描述、长度、状态或普通标识，不能为了命中把它强行标为秘密。没有明确材料时不填写 CVE，不推断产品受影响版本。

## 4. 独立评估设计

样本至少覆盖公开敏感输出、修复版、私有输出、安全状态/长度、未知格式、同名调用与不可分析输入。由独立人员审查标签；存在争议的样本保留 unknown，并记录原因。

报告同时列出总样本、模型适用样本、complete、partial、not_analyzed、failed、unknown、候选及经复核漏洞。Precision / Recall 只能基于定义明确且真值有效的评估子集，并明确分母；未知和未分析样本不得偷偷当作安全样本或检测成功。调参使用开发集，不能反复看留出结果后再把它称为独立测试。

现有 32 个旧控制与 39 个新控制继续用于回归，证明实现行为是否稳定，不能用于宣称真实场景准确率。

## 5. 可选 PoC 的设计边界

只运行获准的 Docker Worker 与注册 Harness，固定镜像 digest、源码提交和构建配置。使用合成敏感材料，网络关闭、源码只读、临时目录可写，并设置资源与超时限制。不要在宿主机直接运行待测历史组件。

至少比较旧版本、修复版本与安全对照，重复运行并保存日志采集方式、日志公开/隐私状态及读取主体权限。单纯出现日志只能证明组件行为；还需实际证明越过预期读取边界，才能进一步讨论泄露影响。当前尚未执行这些步骤。

## 6. 主要风险与处理

| 风险 | 处理 |
| --- | --- |
| 宏或解析限制阻塞覆盖 | 优先最小前端事实与可解释准入，保留 partial / not_analyzed |
| 历史材料并非秘密 | 保留硬化线索分类，不强制升级漏洞标签 |
| 为命中样例修改模型 | 先固定语义依据，新增模型独立版本与对照 |
| 合成控制造成过高信心 | 单独开展冻结后的独立评估，公开适用与未知分母 |
| 动态现象被当产品漏洞 | 区分组件复现、非授权读取、产品可达性与版本影响 |

## 7. 下一轮建议验收清单

- 一份最小接口决议及事实样例；一个受阻文件的正式覆盖对照。
- 两组历史线索逐项核验表，包含 unknown 与排除依据。
- 若扩展模型，提供新版本模型卡及正负/未知控制；否则说明不扩展理由。
- 独立评估的冻结记录、来源与标签规范；实际执行后才提供准确率。
- 满足条件才提交隔离 PoC 结果，否则提交环境与证据缺口。
- 保持 D 目录开发范围、复用公共平台、草稿审核与候选/确认漏洞分离的纪律。

建议首先由队长审核 D2 PR 与接口需求，随后开展单文件覆盖试点；不以立即扩大扫描范围代替解决已知覆盖阻塞。
