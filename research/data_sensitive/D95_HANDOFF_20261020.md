Implementation: `c4605710ac517ca5b61f48fef03b31860fb88966`, sensitive detector
`0.21.9` → `0.21.10`. Baseline owner
`82827ca79e8b71505b9941f5cad7f50e4695e748` merged without conflict as

## Concrete failure and bounded correction

The `for` initializer declares a new pointer whose lifetime ends with the loop:

```cpp
void Callback(const char *key, bool flag) {
    unsigned outer = 0, inner = 0;
    unsigned *p = &outer;
    for (unsigned *p = &inner; flag;) { break; }
    *p = (unsigned char)key[0];
    HILOG_INFO(1, "%{public}u", outer);
    HILOG_INFO(1, "%{public}u", inner);
}
```

Before, direct detector and Runner incorrectly reported only the `inner` log and missed
`outer`. The declaration was evaluated into the enclosing state and never restored.
The fix snapshots loop entry, records names declared by header declarations, performs
the existing conservative loop merge, then restores only those declared names. The
correct `outer` log now carries the material-write dependency; the `inner` log is absent.
No if/else join algorithm or general alias analysis was added. Existing outer pointer
mutations in loop bodies still merge conservatively instead of being undone.

`D95_probe_loop_scope.py` freezes entire source revisions into separate snapshots and
executes each in a fresh process. Its seven-line input yields direct/Runner line 6 before
and line 5 after. The complete observations and input SHA are embedded in
`D95_VALIDATION_20261020.json`.
