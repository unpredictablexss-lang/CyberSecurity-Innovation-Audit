## Bounded pointer/slot model

A private PointerTarget record tracks raw pointer targets in local state. Only simple
single-level raw pointer declarations, direct address syntax, already tracked transparent
copies and one direct member slot are modeled. Branch disagreement, scope escape/shadow,
pointer rebind, an unsupported address or a pointer variable passed by address invalidates
the target claim. Partial parsing, visible relevant macro changes and overloaded address
operators withhold bound status.

Known local p=&scalar and a transparent pointer copy propagate material to scalar, then to
its real consumer. Direct &object.member and p=&object followed by p->member are covered.
A writable helper parameter uses an independent *parameter slot, with single member slots
such as *parameter.count. A known call-site destination maps those slots back to caller
storage. Reference/value outputs retain their existing bounded behavior; this is not a
general reference, union, heap, pointer-arithmetic or multi-level alias analysis.

When a target is not bound, material writes still produce an unresolved candidate; useful
may-flow is not treated as complete proof. Known literal/ordinary overwrites do not invent
sources. No generic through-pointer taint-kill theorem or runtime memory validity is claimed.

Actual source/copy/format output models write pointee slots. Passing an input pointer or
assigning a new value to the callee's local pointer variable is not itself a pointee write.
The helper summary therefore ignores those pointer values as output. Tests distinguish a
read-only input, a local out-pointer rebind, real memcpy output and direct *out assignment.
Pointer consumers can read actual pointee material without conflating that with a pointer
address being a secret; normal logging-format obligations still apply.

Macro-overridden helper calls retain an unresolved candidate even if the visible body only
writes a literal. The visible body is still inspected for positive evidence, preserving the
older T88 control with a real same-name log body. No apparently clean body erases an
unresolved macro call.

## T93 cast regression and repair

The first D94 implementation made the original scope 26->27 by exposing an older heuristic:
`*privateKey=static_cast<PrivateKeyInfo *>(CfMalloc(...))` at358 was sourced from the cast's
type name. T93 reduced it to the decisive synthetic nullptr control:

```cpp
struct PrivateKeyInfo { int unused; };
void sample(PrivateKeyInfo **output) {
    *output = static_cast<PrivateKeyInfo *>(nullptr);
}
```

Owner baseline produced0; first D94 produced1; final produces0. This was a concrete
over-candidate regression, not a newly established real flow. It is retained in the frozen
three-stage probe record. No source is justified merely by a cast's target type name.

The repair recognizes reserved C++ named-pointer-cast AST shape (template_function,
type_descriptor, abstract_pointer_declarator). Its value propagates operand flow, while
the cast itself is not modeled as an API escape/source. Operand effects are still analyzed.
Material operands remain material; visible cast-keyword/nullptr macro overrides retain
normal unknown handling. Scalar/user conversions outside this narrow shape are not newly
classified as safe. This is not an arbitrary function-name whitelist.
