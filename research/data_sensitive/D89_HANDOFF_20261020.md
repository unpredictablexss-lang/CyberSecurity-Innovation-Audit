## Reproduction and bounded provenance

At fixed certificate source `e270363a042bf8f0126881c76d1341ad457cc187`,
`napi_cert_utils.cpp:349` logs `CERT_PASSWORD.c_str()` in a failed-property message.
`napi_cert_defines.h:203` defines that immutable string as `"password"`; lines 342/347 use
the same symbol as a NAPI property key. The baseline reports its name-derived flow as an
unresolved escape through LOGE, rather than establishing password-byte output.

The new exclusion requires all of the following:

- D87's exact global constant/namespace/include binding, plus an already processed NAPI
  read-key role for that same constant in the same actual function. Proof does not leak
  between functions or different constants on one source line. Binding records now include
  namespace, symbol name and declaration byte position as well as source hash.
- One visible `LOGE` object alias to `CF_LOG_E`, with either one unconditional definition or
  a complete mutually exclusive if/else pair of definitions. Sequential redefinitions,
  ambiguous aliases, undefinitions and unproved alternatives do not qualify.
- The HILOG terminal matches literal prefix/suffix plus the formal fmt argument and a
  single forwarded variadic tail. Prefix conversion slots must match the added function/line
  metadata. Unknown metadata expressions or extra/duplicated variadic arguments do not qualify.
- The actual fallback `CfPrintLog` summary is credited only at exact original path
  `frameworks/common/v1.0/inc/cf_log.h` and SHA-256
  `489ea3537091147d5bec365471698f3d5d177dbc86473beb25fd7bc906beccb9`.
  An arbitrary same-name function is not a log proof. The complete immutable source includes
  its variadic formatting body and both macro definitions; both branches must satisfy roles.
- The original log format is literal and has matching arity. Only an already bound schema
  constant in a string conversion's value slot is excluded. Width/precision and escaped-percent
  accounting remain intact; format itself and every other sensitive operand keep normal analysis.

This identifies a fixed schema string operand, not arbitrary data as safe just because the
callee is named LOGE. Unknown helpers, real password arguments, private operands, partial/missing
headers, unsupported formats and same-name local bodies retain candidates.

## T88 implicit-metadata failure and repair

T88 found that caller `#define __FUNCTION__ password` changes the implicit public prefix slot
into actual password output, even though the explicit operand is a schema key. An exact formatter
file hash cannot lock the caller's preprocessor environment.

The repair withholds proof for visible selected-source define/undef overrides of terminal/module
identities or `__FUNCTION__`, `__FILE__`, `__LINE__` and the variadic token. It also rejects
alias definitions outside the proven direct-include graph and checks call-site local shadows
before using cached header evidence. Thus a selected transitive header's override is not ignored.
An unknown/overridden macro environment stays an unresolved candidate; it is not interpreted as
a known safe prefix. The selected static scope is not asserted to be a full product build environment.

T88 independently retested the repaired implementation: all 13 methods passed. With the actual
unmodified fixed cf_log.h bytes/path/SHA, an additional synthetic caller was checked by T88:
no override gives direct/Runner `0/0`, while file/function/line metadata replaced with password
input each gives `1/1`. The known original header remains unchanged in these controls.

Developer controls include the same guard mechanism for a synthetic explicitly reviewed fallback
identity, actual-material and mixed operands, unknown formats, `%`/star mapping, prior-role locality,
same-line different-symbol identity, conditional definitions, visible redefinitions, unknown helpers,
missing/partial/duplicate headers and call-site terminal aliases. Synthetic review-table injection is
labelled as a test-only model, not upstream fallback proof.

## Limits

This is a bounded source/constant/API/macro argument model. It does not run a preprocessor,
resolve general include search paths, prove compiler API identity, model arbitrary wrappers,
generalize the fallback function by name or prove production log exposure. Literal spelling,
candidate count and model self-evaluation are not independent accuracy labels. The source remains
unknown-profile candidate analysis; no product vulnerability or formal Precision/Recall is claimed.
Profiles for other fallback revisions require their own exact source evidence and tests.
