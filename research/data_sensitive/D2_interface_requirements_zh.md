# 队友 D：D2 后续接口需求

日期：2026-10-17。性质：待负责人评审的接口需求，不代表公共接口已经实现或获准修改。

## 1. 需求目的与现状

D2 已在 D 模块内修复局部传播，但正式固定范围扫描仍为 0 complete、3 partial、6 not_analyzed。下一步需要可追溯的函数、错误区域和日志操作数事实，以便负责人判断哪些局部分析可以准入。

继续复用现有 SourceUnit、ScanContext、Finding、Obligations 与 file_outcomes 等机制。D 不另建扫描平台，不自行修改 Runner、数据库、Catalog 或面板。下文名称是概念字段建议，最终名称与结构由公共接口负责人统一。

## 2. P0：最小必要事实

| 事实组 | 建议内容 | 用途与缺失行为 |
| --- | --- | --- |
| 源码身份 | 仓库、commit、tree、blob、文件 SHA-256 | 防止不同提交或文件事实混用；不匹配则拒绝绑定 |
| 事实生产身份 | 解析器及版本、配置 profile、事实生产器及版本 | 支持重放；信息不足时记录限制 |
| 函数与错误区域 | 稳定函数 ID、起止范围、解析错误/缺失节点范围、依赖限制 | 判断局部事实资格；不能仅凭函数未重叠错误就自动准入 |
| 声明与绑定 | 声明 ID、作用域、引用到声明的绑定 | 区分同名局部变量、函数和 API；无法确定时 unknown |
| 局部值关系 | 赋值左右项、参数位置、表达式身份及源码位置 | 追踪材料流向；不得声称已有跨函数证明 |
| 日志参数映射 | 调用身份、格式参数位置、值参数序号、槽位公开/私有属性、未解析格式原因 | 区分秘密是否进入公开槽位；动态或 PRI 格式未知时保留限制 |
| 可选局部退出事实 | fallthrough 是否存在、return/break/continue/throw 及位置、未知上下文 | 改善局部分支解释；不得凭此制造完整 CFG |

头文件的声明、类型和宏信息应作为独立事实提供，不能要求其存在函数体才能贡献信息，也不能把声明解析成功等同于数据流扫描完成。不要直接将 D 私有 AST 对象写进公共协议。

优先试点 `auth_session_key.c`：确认宏与类型依赖，再由负责人决定错误隔离、partial 文件准入与最终覆盖状态。研究探针看到的 15 个无直接错误重叠函数只作为排查线索。

## 3. P1 / P2：后续扩展

| 优先级 | 需求 | 约束 |
| --- | --- | --- |
| P1 | 调用目标及类型身份 | 区分真实 API、同名本地函数、函数指针与宏包装；解析不明时不硬匹配 |
| P1 | 输出参数、返回状态与副作用摘要 | 将材料输出与状态码分开；摘要需版本与适用条件 |
| P1 | Source / Sink 模型来源 | 记录适用仓库、提交、API、字段、参数、语义依据和模型版本；历史模型另行冻结 |
| P2 | 单层调用摘要 | 优先明确 wrapper 的输入输出关系；不据此宣称任意跨函数分析 |
| P2 | 日志运行条件 | 构建变体、日志等级、隐私开关、读取权限及证据来源；静态未知不能替代运行证据 |

## 4. 消费与兼容要求

新增事实应可选、可标明 unsupported / unknown，并携带对应位置与原因。旧检测器无需提供新事实即可继续运行。D 仅在所需事实可用且身份匹配时消费；事实不足时通过现有限制与覆盖机制说明。

不因新增字段改变候选、确认漏洞的定义，不因研究探针解析出局部函数而自行增加 complete 数。输出继续保存文件位置、规则版本和证据引用，不保存秘密原文。

## 5. 接口验收用例

1. return 分支中的敏感赋值不传播到已退出后的公共后继；仍活跃的 else 敏感路径能够产生候选。
2. 内层同名声明离开作用域后恢复外层绑定，日志之后的赋值不反向影响之前日志。
3. 长度、状态码与材料区分；同名本地函数不误套系统 API 模型。
4. 混合 public/private、`%%`、宽度和精度参数正确对齐；未知格式给出限制。
5. 不同 commit/blob 的事实不能混合；缺失类型、调用或宏事实保持 unknown。
6. 固定 9 文件的完整、部分、未分析、失败计数可核对；新增准入前后均保留依据。
7. 既有公共接口使用方与其他队友测试保持兼容，新增事实本身不触发 Catalog / UI 注册。

## 6. 分工及交付顺序

D 提供最小源码样例、期待事实、限制说明和消费侧适配；公共接口负责人决定 schema、准入规则与共享实现，相关语言前端提供解析事实。队长审批模型扩展、评估与后续集成范围。

建议先评审“源码身份＋函数/错误区域＋日志参数映射”，选一个受阻文件试点，验收后再考虑类型/调用摘要。需要交付接口决议、事实样例、兼容测试及固定范围覆盖对照；本文件不要求先完成整套 JS/ArkTS 或通用跨函数平台。
