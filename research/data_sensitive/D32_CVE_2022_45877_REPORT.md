# D32 CVE-2022-45877 组件 PoC 与修复复审

## 结论

**组件历史根因：confirmed。目标 OpenHarmony 产品是否包含受影响代码：unknown。静态扫描命中：candidate。** NVD 记录 OpenHarmony 3.1 至 3.1.4（含）受影响，并将问题描述为跨设备认证期间 PIN 明文发送给对端；CWE-319。该记录不能证明本地某个产品构建包含此组件，也不能单独证明具体设备上的网络可见性。

固定上游源码对照绑定到 distributedhardware_device_manager 的两个 Git 对象。旧提交 97c3d5c7b07a0ab599afcc1464143b255e7dbb68 在 DmAuthManager::OnGroupCreated 中把 PIN 写入 JSON 的 PIN_CODE_KEY，序列化进 authResponseContext_->authToken，再设置响应上下文、生成 MSG_TYPE_RESP_AUTH 并经 SoftBus SendData 发送。修复提交 8bea775dc169bca2d9a1ce57ada2d86cbd179163 删除 PIN 到该 token 的写入，保留本地 authResponseContext_->code；认证 PIN 改由本地交互并传给 HiChain AddMember。此结论由提交差分与 CVE 公告共同支持。

## 复现

需要一个包含上述两个 Git 对象的官方仓库克隆。脚本仅读取 Git 对象，不切换或修改该克隆的工作树：

    git clone --filter=blob:none --branch OpenHarmony-3.1-Release https://github.com/openharmony/distributedhardware_device_manager.git /tmp/dm-cve-2022-45877
    git -C /tmp/dm-cve-2022-45877 fetch --deepen=3000 origin OpenHarmony-3.1-Release
    cd /path/to/CyberSecurity-Innovation-Audit
    .venv-web/bin/python research/data_sensitive/d32_cve_2022_45877_replay.py --repo /tmp/dm-cve-2022-45877 --output research/data_sensitive/D32_CVE_2022_45877_REPLAY.json

本轮实际结果：旧源码 SHA-256 fb4fc22fe6543cd1c1dcb452f0fbab6ae20aee1970d8935ea9f3eebd3ace895a，规则在 dm_auth_manager.cpp:348 产生 1 条 CWE-319 candidate；修复源码 SHA-256 2611593bc66fe32b43b8868cf9e31a48367fd221e196516d05027261c25f6165，该 CVE 形态 0 条。两个 run 均 blocked，因为本规则未运行完整 AST；候选不因此变成 confirmed，0 命中也不等于安全。机器结果：D32_CVE_2022_45877_REPLAY.json。

## 静态规则边界

ohscanner.known_disclosed_cves 0.10.0 只在同一 OnGroupCreated 函数体内同时要求 PIN 字段写入、认证 token 字段、authToken = jsonObj.dump() 以及响应上下文到 SoftBus 响应发送链。独立函数中的 PIN key/SoftBus 调用和已移除 PIN 写入的修复形态是负控制。partial AST 时保留匹配并报告 blocked/unknown。Catalog 中该扫描器仍是显式选择的 research_candidate，不会自动确认。

此处 PoC 是可重复的源码规则差分，不是双设备网络利用 PoC；未构建 OpenHarmony 产品，未抓包，也未证明攻击者能观察传输。NVD 所述“明文”是公开披露结论，扫描器本身不推导 SoftBus 加密状态。修复建议是使用含该上游修复的受支持 OpenHarmony 版本，或将等价改动回移：认证 PIN 不进入经响应通道传送的 auth token，只留在本地认证上下文，并由受信的本地认证交互提供给 HiChain。应针对目标产品的依赖版本与构建清单确认补丁实际生效；本报告无法指定具体首个修复发行版。
