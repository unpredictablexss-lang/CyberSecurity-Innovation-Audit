# 队友 D：后续研究方案

日期：2026-10-17。状态：研究规划，尚未执行；不作为已实现能力说明。

## 一、研究起点与目标

第一阶段已有同函数敏感材料到公开日志的候选原型。32 个合成控制符合测试预期；
固定官方组件 9 文件复测零候选，覆盖为完整0、部分3、未分析6。
这些结果不能证明真实漏洞检出率。下一阶段先解除实际覆盖阻塞，建立真实依据，
再推进独立评估、隔离验证与平台接入。

目标是形成一条可信的“敏感来源→传播→公开日志→非授权可观察→实际影响→修复复验”证据链，
不以增加告警或规则数量为目标。保持 data.log.sensitive-value 首发单规则，避免重复 A/B/C 职责。

## 二、分阶段推进

按以下优先级逐项推进，不以新增规则数量为目标。

### P0：先冻结基线和确认模型边界

1. 负责人确认拟议 ID、单规则范围、源码与日志模型以及 D 目录归属。
2. 核对当前补丁与最新 main 的差异，保留 B 表单修复，避免把无关改动带入 D。
3. 冻结首轮代码、32 个控制、固定源码范围和原始报告身份。
4. 未经审核，不修改 Catalog、Runner、公共合同、UI 或其它队友规则。

交付：审查后的最小变更清单、基线、规则/模型版本、Draft PR。是否接入由负责人决定。

### P1：优先解决实际覆盖阻塞

1. 逐个检查 6 个未分析文件的 AST 失败位置与宏/构建原因，区分头文件声明和真正需要分析的函数。
2. 申请共享语句/表达式事实、类型绑定与日志格式事实；不要私自绕过 Runner。
3. 若负责人批准部分 AST 局部分析策略，先验证能隔离错误区域、保留部分候选并闭合覆盖统计。
4. 在完全相同源码对象和范围上复跑；解释新增/消失候选是覆盖变化、算法变化还是模型变化。

完成标准：明确记录哪些函数/语句可分析、哪些未知；覆盖提升不能以把 partial 改成 complete 来“实现”。

### P2：扩大真实来源与日志人工审查

1. 先在 dsoftbus 固定生产路径寻找日志包装、回调和格式化后的值，不急于全仓扫描。
2. 再选择一个经过机制审查的第二组件，如 access_token 或 update；具体 commit 需重新固定，不能套用当前模型。
3. 为每个来源补齐“为何敏感”、类型/API 来源；为每个 Sink 补齐格式、脱敏、日志等级和生产构建条件。
4. 整理真实安全对照和疑似危险输出；找不到真实危险例时如实保留空结果。

完成标准：每个候选能追溯源码/模型，能列出最可能误报原因；不把 `token` 标识或凭据长度当作密钥。

### P3：建立真实修复对和独立标注集

1. 查找有公开来源的敏感日志修复，固定修改前后 commit 与必要构建条件。
2. 用 vulnerable/fixed/safe/unrelated 四类对照验证同一规则，记录失败和未知。
3. 冻结检测器后由独立审查者标注第二批数据，不把现有 32 个开发样例重新称为 holdout。
4. 只在来源、范围、标签及覆盖满足条件后计算独立指标；未知项单列。

完成标准：可复现的真实修复对或明确的来源缺口、独立标签和冻结后的执行记录。

### P4：验证一个最有价值候选的实际泄露

1. 核对敏感值是否真实产生、代码是否可达、量产配置是否启用该日志。
2. 明确谁可以读日志/诊断文件，是否跨越了授权边界。
3. 在批准的隔离环境中使用合成凭据验证，不读取真实用户秘密，不攻击公开设备。
4. 对比修改前、修复后和无关安全控制，完成重复实验与修复复验。
5. 证据满足门槛后再升级结论、确认影响版本与 CWE；没有依据不关联 CVE。

完成标准：真实入口、触发、可观察性、具体 CIA 影响和修复复验，而非只输出一条日志。

### P5：平台接入与后续扩展

由负责人选择性注册 Catalog、复核统一 Runner/报告和面板显示。先证明首条日志规则有效，再评估诊断凭据与未保护文件转储两条后续规则；跨函数从有明确目标的一跳调用开始，跨组件传播另提接口方案。

## 三、结果评估与停止条件

| 项目 | 需要提交的材料 | 不能宣称 |
|---|---|---|
| 覆盖提升 | 固定范围的文件/函数/区域变化及原因 | 将partial改名为complete就算完成 |
| 候选变化 | 同源码/范围下逐条新增、移除及解释 | 告警下降就是准确率提升 |
| 真实样例 | 来源、commit、路径、敏感语义、日志出口 | 自建样例是真实CVE |
| 独立评估 | 冻结模型、独立标签、覆盖和执行记录 | 开发样例充当holdout |
| 动态验证 | 批准的隔离环境、合成凭据、重复控制 | 单次打印即产品可利用 |
| 最终影响 | 实际读取主体、权限边界、CIA影响和修复复验 | 无依据标注affected/fixed或CVE |

来源或公共接口缺失时保留blocked/unknown并列出依赖，不扩大扫描掩盖覆盖问题；
找不到真实危险正例时如实记录负结果，不删除守卫或降低门槛制造命中。

每阶段记录固定基线/规则模型版本、来源commit/blob/SHA、实际命令、范围、
PASS/FAIL/SKIP、候选/覆盖差异、报告哈希和未验证项。
负责人审查后以Draft PR选择性集成；不得自动ready或merge。

建议下一项最小工作单元：先调查6个未分析文件的解析原因，选一个最小可解决的事实/资格缺口，
与负责人确认后补一个公共能力及正负/未知回归，再在冻结范围复测。
