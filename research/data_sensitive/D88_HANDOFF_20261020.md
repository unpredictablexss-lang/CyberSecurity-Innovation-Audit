# D88 exact empty split C++ linkage syntax recovery

Owner input: `2dd69e99e8038c905d1e81250207365aa911906f`; merged worktree head before edits:
`63063847507b79bb2317f29be52cb390446a39b5`. Sensitive detector: `0.21.4` → `0.21.5`.
Shared parser changes are limited to the same offset-preserving normalization used by the
sensitive detector's private parser. No source bytes, snapshot hashes or public schemas change.

## Reproduction sent to T87 before implementation

The pinned certificate-framework file `frameworks/common/v1.0/inc/cf_log.h` at
`e270363a042bf8f0126881c76d1341ad457cc187` contains an empty linkage body at lines 24–30:

```cpp
#ifdef __cplusplus
extern "C" {
#endif

#ifdef __cplusplus
}
#endif
```

The shared and private C++ grammars initially treat this split linkage as incomplete syntax.
A raw minimal header plus a `Sentinel(7)` probe is partial; blanking only the empty linkage
tokens makes it complete while preserving byte length. The full pinned header has 3,266
original bytes; exactly 11 non-space bytes are changed to spaces for parsing only.

## Narrow accepted form and shared-parser impact

`normalize_empty_cpp_linkage_wrappers(bytes)` accepts only contiguous pairs of these exact
`#ifdef __cplusplus` blocks at top-level declaration scope. The body between the first
`#endif` and second `#ifdef` contains whitespace only. Every preprocessor directive remains.
The function replaces only `extern "C" {` and its matching `}` with same-length spaces.
CR, LF, UTF-8 byte offsets, original call spans and SourceUnit hashes remain unchanged.

Raw-grammar lexical spans protect comments, strings, raw strings and macro arguments.
Visible brace depth and continued-macro-line checks reject embedded function/class/namespace
lookalikes. Prefix scanning advances linearly across multiple matched pairs. The projection
is idempotent, and both call sites apply it only to C++:

- Shared `src/parser/ast.py` derives status and indices from the recovered syntax tree.
- Sensitive `LocalFlow` derives its private tree from the same projection, retaining `flow.b`
  and every trace coordinate against the original bytes.

This does not evaluate preprocessor conditions, generally preprocess headers, remove real
declarations or overwrite a partial status with complete. The parser still decides status.
Unpaired markers, wrong order, repeated openings, extra closes, different conditional
contexts, actual declarations and alternative-branch declarations retain syntax errors.
Even legal nonempty or namespace-scoped linkage forms remain outside this small recovery.
