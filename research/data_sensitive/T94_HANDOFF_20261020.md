## 独立发现、反馈与修复

最小有效 C++ 场景：外层 p=&first，for 初始化器声明同名 p=&second，循环后通过 p 写入 source 首字节并记录两个 scalar：

```cpp
unsigned first=0, second=0;
unsigned *p=&first;
for (unsigned *p=&second; flag;) { break; }
*p=(unsigned char)key[0];
HILOG_INFO(1,"%{public}u",first);
HILOG_INFO(1,"%{public}u",second);
```

for 内 p 的作用域在循环结束时退出，后续写入必须指向 first。基线把 loop header declaration 直接写入外层状态但没有恢复：direct/Runner 都只产生 second 日志候选，漏掉 first。独立复现后立即反馈 D95；修订保存 loop entry、收集 header declaration 名称，并对合并后的 live/exit 状态恢复该声明作用域。没有将普通 body 对外层 p 的重绑定也无条件撤销。

固定对照的相同 source SHA256 为 `d15c6f1d1a9debe73c91a9372cabf85793600eb9bb43eeaeca50672409cbb9e2`：旧 trace `Callback parameter0 -> assign second -> line6 HILOG`，新 trace `Callback parameter0 -> assign first -> line5 HILOG`。first target direct/Runner 0/0→1/1，错误 second target 1/1→0/0。该合成 profile 明确以 Callback 参数 0 为 material source，不使用 key 名字启发式或产品秘密标签。

## 合并与回归控制

其他十个方法基线即通过，修订保持：

- if/else 两支同 target 保留实际日志；不同 target 保留 `unresolved material write`，不把任一 scalar 的日志当成确定已写入。
- 一路 nullptr/未知目标使合并 target unknown；明确 rebind 后恢复新确定 target；return 后只考虑 live 分支。
- 块内 pointer shadow 退出后恢复外层；while 中外层 pointer 可能重新绑定时保持 unknown，不污染两个确定 sink。只有循环 header 内新声明需要作用域恢复。
- literal-only 分歧写不创建 material；真实 memcpy output→sink 保留；未知 target 写保持候选；static_cast(nullptr) 不因敏感类型名创造 source。

fixed harness 逐案保存完整 source、target statement、source SHA、direct/Runner 诊断、ID、coverage 和调用事实。除 for-header shadow 的目标更正，代表 cases 的候选和数据角色不变。未知目标的 unresolved 候选用于保留写入事实，不证明实际目标已暴露内容。
