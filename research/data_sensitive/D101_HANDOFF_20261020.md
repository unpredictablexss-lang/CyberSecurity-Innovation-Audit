# D101 structured handoff: proven builtin comma values retain operand effects

## Problem and implementation

Owner baseline `04d06da236ed46c277fe3b756a3a42c95ce7ab98` merged without conflict as
`b53ed86c2666ea8608e73f8a1adaba2c8c34fe89`. The T99 int-prototyped source fixture
`return(HILOG_INFO(...,value),0)` reported its actual internal log and also falsely
propagated material into the caller's numeric status log. Simple `(key,0)` sequences
likewise inherited the discarded source operand.

Implementation `ecaa9b0c32df2fb1688027a1b0e2af67c79bf540`, detector 0.21.15 → 0.21.16.

- `src/ohscanner/detectors/data/comma_values.py` adds a narrow source-local type proof.
  It requires one complete translation unit, complete selected inputs/shared AST, no
  preprocessing and no class/struct/enum/alias/namespace/operator-comma environment.
  It accepts only explicitly fundamental/pointer literals, uniquely declared live
  parameters/locals, unique direct global primitive-return declarations/definitions
  with compatible arity, parentheses and limited pointer/subscript syntax. Repeated
  declarations, callable shadow, overloads and unsupported types reject the proof.
- `sensitive_exposure.py` uses only the final operand's value when that proof succeeds.
  Its effects traversal is unchanged: every operand's calls, logs and assignments are
  still analyzed. Unknown comma bindings retain existing whole-expression may-flow.
- `tests/detectors/data/test_d101_comma_result_proof.py`: seven developer methods.
- `D101_probe_comma_values.py`: eighteen frozen full-source/fresh-process observations,
  including operand AST/byte/type-proof records, module SHA and a separate parser gap.
- `D101_VALIDATION_20261020.json`: complete observations, raw/source hashes, diagnostics,
  coverage, type-proof limits and immutable independent-test identities.

This is not a global comma-text rule, function-name whitelist or general C++ type system.
Unknown primitive-return call behavior can still be an escape candidate: knowing its
declared result type does not establish safe effects or public arguments.

## Explicit remaining parser/type boundaries

Current Tree-sitter parses legal `(out=key,0)` as root ERROR/partial. Direct analysis
retains the true output-log candidate; Runner excludes the ineligible unit and is blocked/
not_analyzed. This unchanged parser gap is recorded separately, not passed as safety.
The extra-parenthesized `((out=key),0)` control parses complete and preserves the actual
output log in both pipelines. No shared-parser change is included.

Multi-file binding, preprocessing/build context, classes, aliases, namespaces, general
overloads, conditional/assignment/cast type inference and exact compiler identity remain
outside the proof. Such expressions retain may-flow. Material in the final operand is
not sanitized. Tests run scanner Python on source; no target-code execution, second-layer
model work, public task-tree modification or push was performed.
