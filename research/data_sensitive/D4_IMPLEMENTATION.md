# D4 实现说明与结果边界

D4 在历史数据流研究原型中增加可审查的摘要扩展字段：`summary_function`、`summary_parameter`、`output_member`、`output_type`、`allocator`、`sink`、`format_index`、`default_private` 和 `format_syntax`。原 TCP profile 省略的字段继续采用旧默认值，不改变它的既有模型含义。逻辑仍要求精确版本模型、唯一且无解析错误的一跳摘要、分配和非空检查、成功返回分支、目标文件与目标函数匹配。

D4 本地复核另外收紧了来源绑定：检测器执行前检查请求快照摘要、上下文文件路径唯一性和源字节 SHA-256；`detect()` 实际收到的分析单元必须逐路径、语言、字节和哈希匹配该请求上下文，且固定 profile 的目标文件必须在本次分析范围内。快照摘要漂移、上下文字节不匹配、输入单元不属于快照、重复路径或目标文件被 scope 排除都会以 `blocked` 返回且不产生候选。这样即使绕过公共 Runner 直接调用研究检测器，也不能把 context 外文本误配到固定历史 profile，也不会将漏掉目标文件的扫描说成 clean。

新增设计控制覆盖不同摘要函数名、不同结构字段/类型、不同参数位置、不同分配器、不同 sink 名和格式参数位置；并验证 profile 声明默认私有时不报告、相同代码位于无关函数时不报告。补充的版本绑定回归测试覆盖输入字节偏离快照、快照摘要漂移、重复路径和目标文件不在扫描 scope。控制是合成设计测试，不是上游真实扫描样本或独立准确率评估。

真实链路现在证明请求发送侧确实构造 `FLAG_REQUEST` + `SESSION_KEY`；但接收侧日志发生在 `FLAG_REPLY` 分流之前。因此报告必须把“请求 JSON 可含密钥”与“回复 JSON 不含密钥”分开说明，不能说所有解密输出都含秘密。

没有更改公共 Runner、Catalog、前端、接口契约、面板、数据库或队友 A/B/C 文件。公共解析器对目标文件的准入缺口仍需平台处理；本分支测试没有把私有研究探针提升为公共检测结果。
