# D102 structured handoff — bounded C++ assignment-comma parsing

## Problem and minimal reproduction

Owner baseline `9b77ae4341979c1fa49c502a74f14be4f87f4aa3` was merged as
`67d2f6a568c7905159bf2d6d45485fe6ab64dbfa`. Valid C++ such as
`unsigned code=(out=key,0);` and `return(*out=value,0);` produces ERROR/missing nodes
in the installed tree-sitter-cpp 0.23.4 grammar. The direct detector can sometimes
see assignment effects, but Runner excludes the parser-partial translation unit.
A nested example even loses that direct flow. This was a coverage gap, not safety.

Raw C parsing of the identical bytes produces the expected expression structure:
`comma_expression(left=assignment_expression(out,key), right=0)`. The C++ grammar's
parenthesized assignment-lhs specialization is a relevant observed conflict; the
upstream grammar source/hash and installed package versions are recorded in the
validation JSON. We did not regenerate the parser, derive its LR states, or claim
a general upstream grammar fix. Grammar content was read from the official
[tree-sitter-cpp v0.23.4 source](https://github.com/tree-sitter/tree-sitter-cpp/blob/v0.23.4/grammar.js).

## Implementation and files

Implementation commit `604d392e56d4deb922304caa2735133282e0cbb1`; detector 0.21.16 → 0.21.17.

- `src/parser/cpp_assignment_comma.py`: inspection-only local AST overlay. It accepts
  an erroneous C++ parenthesized subtree only when a complete, explicitly whitelisted
  C/C++ common expression exists at the exact same byte span and contains a bare
  assignment operand in a comma expression. At most 64 nonoverlapping grafts per unit.
- `src/parser/ast.py` and detector `sensitive_exposure.py`: both use this same helper.
  Shared parse issues explicitly record recovery spans; private analysis retains a
  type/overload obligation. Original C++ outer nodes and underlying tree lifetimes
  are preserved. This is no whole-file C fallback or editable Tree/cursor API.
- `tests/test_cpp_assignment_comma.py`: seven developer parser controls including
  precedence, single call argument, UTF-8/CRLF byte offsets, independent error,
  C++-only rejection, original complete-tree identity, C syntax and outer C++ nodes.
- The current T100 regression test is updated to assert recovered parsing and its
  actual output effect. Historical T100 evidence remains unchanged at its fixed SHA.
- `D102_probe_assignment_comma.py` archives complete before/after `src/` and runs
  eleven source controls in fresh processes. `D102_VALIDATION_20261020.json` embeds
  full developer observations and exact independent commit/blob/SHA references.

No bytes or line endings are rewritten by this helper. ERROR/missing nodes outside
admitted grafts remain errors. Templates inside the candidate, lambdas, explicit
operator calls, typeid, comments/preprocessing inside parentheses, malformed syntax
and unmatched original parentheses spans reject recovery. C++ syntax outside the
recovered expression retains its original C++ nodes. Recovery establishes syntax,
not builtin-comma typing, overload identity, candidate safety or runtime impact.

truncated raw C++ parentheses span. No exact-span matching C subtree exists, so it
remains partial and Runner blocked/not_analyzed. This is a separate unresolved
coverage gap, not a passing safety result.

summary. Recovered parsing preserves a named unresolved material-write candidate;
its already-complete double-parenthesized baseline has the same summary limitation.
