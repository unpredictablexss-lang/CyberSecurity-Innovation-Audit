# D37: MTP full-length xattr string termination (CVE-2026-28751)

Date: 2026-10-19
Detector: ohscanner.known_disclosed_cves 0.13.0
Conclusion: **the pinned 6.0 pre-fix source has a full-capacity xattr value that is not NUL-terminated before C-string use; the detector emits a candidate. The linked fix prevents this source shape, while product applicability remains unknown.**

## Evidence

The [OpenHarmony April 2026 security bulletin](https://gitcode.com/openharmony/security/blob/master/zh/security-disclosure/2026/2026-04.md) lists CVE-2026-28751 as an input-validation issue in filemanagement_storage_service with local denial-of-service impact and links the 6.0 release fix. The exact 6.0 source fix is commit aa3abd7e24050ef284064d9f800a3bc833d90538, titled “修复MTP代码漏洞”; its parent is d55dc1f9195bf0301680a788d5b9487e67332382.

In the parent source, NotifyMtpMounted allocates exactly MTP_DEVICE_NAME_LEN bytes, passes that capacity to getxattr, and adds a NUL only when len < MTP_DEVICE_NAME_LEN. A full-capacity return skips termination, then the value is passed to std::string(value) and logged as a C string. The linked patch allocates MTP_DEVICE_NAME_LEN + 1 and accepts len <= MTP_DEVICE_NAME_LEN before writing value[len] = '\0'. The inspected current 6.0 head retains the fixed shape. The replay verifies tree, blob, and SHA-256 for the pre-fix commit, fix commit, and 6.0 release head. The inspected 5.1 source has no NotifyMtpMounted/getxattr signature in this file; that absence is not treated as a security verdict.

## Detector and component-shape harness

The rule is limited to the volume_manager_service.cpp NotifyMtpMounted body and requires all of: exact-capacity allocation, getxattr bounded by MTP_DEVICE_NAME_LEN, strict len < capacity guard for termination, and later std::string(value) use. The positive/fixed/unrelated unit test checks those same constraints.

A source-shaped ASan harness supplies exactly MTP_DEVICE_NAME_LEN non-NUL bytes and reproduces heap-buffer-overflow while constructing std::string in 3/3 runs. A safe control reserves one extra byte, writes the terminator at the full-length boundary, and reports no ASan error in 3/3 runs. This models the source defect and fix, not a build of filemanagement_storage_service, attacker reachability, or an OpenHarmony product exploit. CVE classification in the rule uses CWE-125 for the observed out-of-bounds read mechanism; the public bulletin categorizes the issue as improper input validation.
