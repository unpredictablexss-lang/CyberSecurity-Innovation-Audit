# 队友 D D4 后续研究方案

## 研究目标

把“源码证明请求构造了密钥字段且旧代码把解密消息写入日志”推进到可复核的构建、运行与访问边界证据。目标是判断现实可达性和安全影响，不预设漏洞成立。

## 阶段一：锁定构建

- 由平台/产品负责人提供实际源码基线、产品 build target、GN args、宏定义、依赖版本和产物镜像 digest。
- 证明 TCP Direct 源文件和 `SoftBusLog` adapter 进入目标构建；记录其余变体和未覆盖范围。
- 对照 `D4_SOURCE_MANIFEST.json` 中的 commit、tree、blob 与 SHA-256，任何不同版本先重新审查，不复用旧 profile。

## 阶段二：本地 AST 准入

- 平台负责人实现局部分析单元及精确依赖证据接口（见接口需求）。
- 已用固定 commit 对应的 10 个真实源文件执行研究型 Detector 重放，得到旧版 1 个、后版 0 个候选；两版均 6/10 文件 partial 且总体 blocked。平台负责人实现局部分析单元及精确依赖证据接口后，D 再在公共 Runner 上重跑目标文件，要求请求路径、DecryptMessage 成功分支和 sink 操作具有来源 span 与明确覆盖状态。
- 加入实际安全路径、同名无关函数、缺依赖/宏 partial 对照；不使用人工确认的候选去调参数再冒充独立 holdout。

## 阶段三：隔离运行验证

- 使用平台现有 Docker Worker 或正式设备测试环境；先核验 worker 隔离、镜像 digest、输入范围与回滚方式。
- 分别驱动正常请求、回复、失败解密、无 SESSION_KEY 消息和长短边界消息。只记录测试密钥或无敏感占位值，不采集真实用户密钥。
- 固定源码显示 `SoftBusLog` 用 256 字节缓冲、`[TRAN]` 前缀和 `vsprintf_s`；按已查 Secure-C 接口契约，`destMax` 包含 NUL，超长返回错误并跳过原始日志输出。运行时需锁定产品链接的 Secure-C 版本，实测边界前/边界/超长三种长度的返回值与输出，确认目标实现与契约一致；不要把预期写成“截断输出”。
- 记录 SoftBus 阈值来源、产品是否覆写默认 0、HiLog 全局/域/tag 等级、隐私开关、是否使用 `SOFTBUS_PRINTF`，并保存最终日志内容（仅使用合成密钥）。

## 阶段四：访问权限与影响

- 由平台安全负责人列出 ring buffer/持久化日志位置、读取主体、权限策略和产品配置；开发者 `hdc shell hilog` 能查看不等于普通应用可读。分别以 shell/hdc、普通应用 UID、明确未授权身份测试并保存允许/拒绝结果。
- 证明攻击者能否访问日志，以及字段是否可复用或可解码；检查日志保留、导出和脱敏策略。
- 只有完成来源可达、日志实际输出、未授权读取和可验证影响链后，才由人工审核决定是否认定漏洞。

## 阶段五：规则评估

- 冻结 Detector/Profile 版本，再由独立人员准备盲测的真实安全、同名无关和真实风险样本。
- 单独报告覆盖分母、未分析范围、候选、人工确认、误报/漏报与置信区间；样本不足时不报告 Precision/Recall。
- 先用现有 Worker 做人工选定单样本验证；没有授权前不扩展至大规模社区扫描，不建立第二套 PoC 平台。

## 停止标准

构建/解析/运行/权限任一环节缺证据时，将状态保留为 unknown 或 partial，并附来源和缺口；不要将“旧日志已删除”直接写成漏洞修复已验证。
