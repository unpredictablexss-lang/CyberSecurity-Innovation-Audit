## Minimal reproduction

The regression test uses this reduced shape:

```cpp
namespace panda::ecmascript::kungfu {
void BuiltinsTypedArrayStubBuilder::Broken() {
  IR_IF (condition) { first(); } IR_ELSE { second(); }
}
void BuiltinsTypedArrayStubBuilder::Filter(
    GateRef glue, GateRef value, GateRef count,
    Variable *result, Label *exit, Label *slowPath) {}
}
```

The `IR_ELSE` form produces an `ERROR`; Tree-sitter ends the namespace node early, recovers `Filter` as a `translation_unit` child, and leaves the exact namespace out of `qualified_name`. Replacing the macro-shaped control flow with ordinary `if (…) { … } else { … }` keeps both functions inside the namespace's `declaration_list`.

The added controls cover a complete namespace/class/method structure, missing namespace, an overload and changed arity, same method name under another class owner, and a partial AST. A partial-tree helper case retains the exact unqualified helper signature but asserts `visible_origin_operation_unverified` and `not_analyzed`; no global name whitelist or owner binding was introduced. Function start/end bytes, source line, and the original function source slice are asserted.

For the actual file, the production-default `analyze_unit` returns `not_analyzed` with `target_not_resolved_in_partial_ast`. The isolated helper repro reaches `visible_origin_operation_unverified`. An exploratory exception-guard call with explicitly unqualified `Filter`/`Map` names can report local `matched` paths, but this is not accepted as proof that those methods belong to the reviewed namespace owner. No owner inference was added.
