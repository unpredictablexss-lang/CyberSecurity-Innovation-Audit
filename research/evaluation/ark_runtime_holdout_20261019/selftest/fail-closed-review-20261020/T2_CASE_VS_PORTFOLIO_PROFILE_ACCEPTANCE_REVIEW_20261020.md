## Required D5/T5 correction before accepting a case profile

1. Define one canonical target key: product, board/device, build/image identifier, source release/branch, immutable locked manifest commit and manifest digest.
2. Require a single evidence closure for source pair, product component revision, GN target/action and successful compile/link, args/config, compiler/linker/target triple/sysroot, compile database, generated inputs and transitive include closure, preprocess command/macro log/TU, and shipped binary/image digest plus source-to-product integration mapping.
3. Include all profile manifest `required_identity_fields` in the case acceptance: commit/tree/blob/source SHA, detector/rule version, scope/profile, config hash, parser identity, and product toolchain identity. Make T5 independently verify each field and its relation to the same candidate/build.
4. Preserve case status separately from portfolio status; IBS5YG acceptance updates only its case row. Portfolio PC-1 remains blocked until all 16 required case profiles pass.
5. Re-audit the revised D5 manifest by its new digest. Do not promote UNKNOWN to PASS from source ancestry, an unrelated build, a mutable manifest URI, or a matching hash detached from the expected path/revision/action.
