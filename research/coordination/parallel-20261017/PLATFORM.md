# 平台线：源码与审计规则规划

平台线是可独立开发的 sources/planning 模块；集成人仍负责现有 API/SQLite/Worker/catalog/协议与全局接线。
使用自己的 env.sh、18774、data 和 repo-cache，不写公共源码 checkout 或正式任务库。

第一交付：实现一个纯规则规划函数，输入固定源码的语言/文件范围、已注册检测器的实际适用元数据和用户选择，
返回可执行建议、跳过/不支持理由、需人工决定项以及版本/来源绑定；它不是扫描结果，也不能把无适用检测器读成安全。
只消费调用方传入的 metadata，不绕过 catalog 新建另一套生产注册表。
初期写 `src/workbench/planning/` 和 `tests/test_audit_plan*.py`；源码清单适配放 `src/workbench/sources/`。
不要先建数据库表、接新 API 或后台扫描；交最小接口申请由集成人完成接线与兼容性测试。

验收：空仓库、混合语言、未知语言、没有适用检测器、用户手选不适用规则、partial/missing 元数据、固定版本变化。
规划可重现，限制明确；不隐式 fetch、不运行被审计源码、不调用真实模型、不自动升级结论。
现有扫描 ID/report/v1读取必须保持兼容。新增测试从仓库根运行，scope check 零越界，按模板交付。
之后 Agent/验证编排是单独任务，不能用计划函数通过来声称已具备这些能力。
