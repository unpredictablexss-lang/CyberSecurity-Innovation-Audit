## 可以纳入披露回归台账的结果

- **CVE-2023-25176：匹配。** DATA-05 ipc.tlv.fixed-width-length 在固定长度 TLV 读取处为 1→0；两端文件均 partial。
- **CVE-2023-0035：匹配。** AUTH-01 ipc.relay.descriptor-boundary 为 1→0；修复是在成员函数指针派发前校验 interface token；两端 partial。
- **CVE-2023-0036：匹配。** AUTH-01 同类 descriptor 闸门为 1→0；两端 complete。
- **CVE-2025-26691：匹配。** AUTH-02 ipc.auth.missing 七个方法候选随 caller/system-app 与权限检查变为 0；两端 complete。修复端是 911c6c99…；旧记录曾把此端点误当成 vulnerable 输入，本次按正确方向重跑。
- **CVE-2025-26693：部分匹配。** 修复端 GetReqPermissionsInner 的身份/敏感数据候选消失，入口描述符候选仍保留；两端 partial。
- **CVE-2025-27563：部分匹配。** 三条与修复方法对应的 caller-class 候选消失，但 RemovePermissionUsedRecordsInner 仍留身份/授权候选；两端 partial，需查清 token 类型与服务角色语义。
- **CVE-2025-27247：匹配。** 使用 service stub + service implementation 双文件范围后，ipc.auth.privileged-app-bypass 候选随默认输入法授权移除而消失；总数 4→3，其余是独立观察；两端 partial。单文件范围会漏掉此跨文件规则，故不得引用最初 0→0 运行。
- **CVE-2025-25212：匹配。** 无界观察者候选随 per-(userId, PID) 限额/清理增加而消失，总数 3→2；其余 stub 访问候选不属该根因；两端 partial。

“匹配”是负责人约定的公开修复源码回归标签：只标记该 CVE 与相应固定提交对的研究台账，不得复制到同规则其它候选，也不得改写扫描 finding 的 severity 或 validated_vulnerability。

## 暂不作为吸收成功的两组

**CVE-2022-42463：候选跨修复端持续。** 当前规则在漏洞端与修复端均各产生一条 AUTH-06 相关候选；公开补丁加入 session-name 白名单，但使用 strncmp 比较白名单长度。规则要求拒绝路径的精确身份语义，不能把前缀比较记成已证明完整相等。修复版残余可能是未覆盖的边界，也可能是有意的协议前缀语义；目前只标为 candidate / unresolved，不是再次确认的 CVE。后续需要检查 sessionName 编码/长度约束、上下游合法值和客户端发送构造，建立正例、前缀反例、固定/safe 对照。

**CVE-2024-39775：补丁差分不足以支持安全根因结论。** AUTH-07 在 10→8 中减少的两条位于 OnResetFactory，恰随 PR 将 Binder transport return code 改成拒绝码；本次同时纳入并固定绑定 proxy 源码。NetStatsServiceProxy::SendRequest 会读取 reply 中的业务错误码，多个代理在解码结果前检查调用结果；同一消费模式覆盖其余八条。当前证据支持“transport/reply 状态表示不一致”这一源码观察，但未证明授权拒绝会被绕过，也未证明该状态变化是公开公告所述 OOB 根因。AUTH-07 的 consequence 已改成 unknown，不再默认归为 unauthorized_effect；规则候选仍需谨慎复核。
