# 实验材料总览与复现入口

## 项目目标与证据等级

OHScanner 面向固定 Git 版本的 OpenHarmony 源码审计。主流程是：冻结仓库与提交 → 规划代码范围 → 多检测器产生带源码哈希的候选 → 保存覆盖和证据义务 → 人工/受控验证 → 修复版本重验 → 报告。评委材料按 A/B/C/D 算法研究、负责人平台、Agent/LLM 和外接盘大规模实验分区，便于分别判断能力和限制。

判断时使用以下层次：

1. **静态 candidate**：规则观察到一个可能机制，未证明完整调用路径和影响。
2. **固定公开修复对回归**：同一检测器在公开漏洞修复前后观察候选差异；这是规则对照证据，不等于产品可利用。
3. **组件 Harness 复现**：受控组件或源形态触发 ASan/UBSan/行为差异；只有被测组件/源形态范围内成立。
4. **产品级确认**：必须再证明目标产品构建、可达入口、攻击者控制、影响和修复重验。没有这些证据就保留 `unknown`，不以 CVE 名称、静态告警数量或 Agent 结论代替。

当前材料没有把静态候选升级成产品级漏洞；产品级 `validated_vulnerability` 维持 0。每一份源报告的历史统计只对报告指定 commit、Detector 版本和 scope 有效。

## 外接盘 OpenHarmony-100 与 B 线披露回归

`外接盘_OpenHarmony100/` 保存了 G 盘 `campaign-100-20261017/results` 的可审阅总结、ABCD 线分析、未扫描仓库覆盖说明、候选数量拆解、detector 统计，以及一份完整的 B 线 0.12.1 vulnerable/fixed JSON/Markdown 复测快照。原始 Excel 的多个时间版本彼此重复且单份解压超过 1 GB，因此不入 Git；总览清单保存其路径、大小和 SHA-256。对照版本请以报告内的 Detector/模型版本和 Git commit 为准，不把 0.12.1 外接盘快照说成 B 线当前版本；B 线随后 0.12.12 报告另存于 `B线/当前分支_v0.12.12/`。

复现建议：先读 `执行总结.md` 与 `ABCD线实测分析与改进建议_20261018.md`，再读未扫描范围说明；针对 B 的复测，先检查 manifest 的输入 commit、tree、scope、Detector 版本和每个 JSON/Markdown 的 hash。没有本机固定 Git 对象时，先从来源恢复准确对象。

## Agent / LLM 实验

[评委版工作流说明](AgentLLM/大模型层Agent工作流与实验设计_评委版.md)区分离线 Fake Provider 与真实 Provider。真实 DeepSeek R0/R1/R2 历史实验中，R1 只接受一条带固定源码位置的观察、仍有义务未解；R2 结构校验失败并被 fail-closed 丢弃。另一份 2026-10-19 离线烟测使用 Fake Provider，证明任务流和固定源码只读工具接线，不证明真实模型质量。两种结果都不能作为“Agent 提升准确率”的证据。

真实模型实验复跑时必须单独记录模型/版本、提示词、工具策略、预算、实际 token、失败和完整响应校验；不得把旧工作区的模型配置或 API 密钥提交到仓库。当前复现材料没有密钥。

## 本地复现通用步骤

1. 在新工作区克隆本项目，并记录本包分支 commit 与各材料来源 commit；不要在队友的工作树切换或清理文件。
2. 对照 `来源与版本清单.json` 恢复每个实验的固定仓库/commit/tree。实验输出缺少完整来源绑定的，按原报告的 `unknown` 处理。
3. 对静态扫描复跑，使用报告记载的 Detector 版本、scope/include、完整 CLI 参数和独立输出目录；确认 `complete/partial/not_run` 数量闭合。
4. 对 Harness/PoC 仅在报告声明的本地隔离环境运行，保存镜像 digest、编译器、argv、日志、退出码和输出哈希。容器不可用则记为 blocked，不回退到宿主机执行。
5. 对 Agent Fake Provider 运行报告中所列的独立脚本与测试；对真实 Provider 复跑需要自行确认服务授权和费用预算。本包不含可复用的私有 Provider 配置。
6. 复跑后将新结果作为新记录保存，不覆盖本包中历史快照；逐项更新 manifest/hash，并标清实际验证时间与差异。

## 已知限制与排除项

- 本包是按可审阅性筛选的完整材料索引，不是所有本地运行数据库、原始源码镜像、缓存和重复中间文件的逐字节归档。
- G 盘 OpenHarmony-100 全量 Excel 保留在线下硬盘，未推入 Git；SHA-256 已记录。多份历史 Excel 只在硬盘，不把任一旧版本误作最新。
- 原始代码仓库可由其公开上游和固定 commit 重建；本包只收录必要的自研实验脚本/报告，不复制整个 OpenHarmony 镜像。
- 无真实产品固件的构建证明、系统入口证据和完整影响验证时，产品状态为 unknown。
- 不报告未标注 holdout 上的 Precision/Recall；重复源、测试样例和公开漏洞修复对不可冒充独立测试集。
- 面板浏览器、平台服务与静态 Detector 的验收分别报告，UI 正常不代表规则准确。
