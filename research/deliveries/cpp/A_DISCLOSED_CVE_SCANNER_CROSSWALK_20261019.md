## 结论与优先级

1. **真正已有精确漏洞/修复源码差分证据**：curl CVE-2026-92391（通用 `resource_lifetime`，完整解析）；cJSON CVE-2025-57052（显式签名，固定源对与组件控制）；web_webview CVE-2026-27648 和 libtiff CVE-2025-9900（generic/root-site 有候选差异，但 blocked/partial）；storage CVE-2026-25850、CVE-2026-28751 与 libpng CVE-2026-33636（显式源形状正负对，解析或目标配置仍有限）。这些都只证明代码候选机制，不代表产品漏洞确认。
2. **签名存在但必须继续补 source/fix replay 或根因模型**：CVE-2026-46675、CVE-2026-67216、CVE-2026-67215、CVE-2025-25212、CVE-2022-45877、CVE-2026-58313、CVE-2026-28733、CVE-2025-27247、CVE-2026-92392、CVE-2026-9079。显式规则的存在不能自动记作“已有漏洞可以扫出来”；关注固定侧残留、缺失解析、版本绑定及跨函数语义。
3. **通用 detector 只是家族可达、不是根因保证**：CVE-2025-0587 / 23420 已 current CLI replay，需根因级候选映射；CVE-2025-26690 仍缺 current replay；CVE-2026-33416 虽有通用 lifetime 候选差分但解析不完整；CVE-2025-20042、21098 保留原 A 线 N/A 口径。CVE-2026-34757 暂无独立审案例。
4. 核心队列：解除 parser/context blockers（46675、33416、27648、28733、92392），复核 23420 候选与 patch digest，补 cJSON 真实源/fix 对照，并恢复 CVE-2025-26690 当前 CLI replay；之后再补产品构建、调用链与攻击者控制。产品级漏洞状态对全部案例仍按原审查边界保持 unknown。
