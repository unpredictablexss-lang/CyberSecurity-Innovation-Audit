# C-line TypeSafety contract and validation status

Status: **research only; public Runner admission remains blocked**. This document freezes the boundary for the bounded Ark Runtime type-origin model. It is not a product vulnerability determination.

## Admissible analysis subset

The research adapter supports only the exact replay pair in `RuntimeTypeModel.source_profiles`: parent `830e85b40240677039719fcbf14f721ad3b19050` / tree `579712c1ebbb703d17cea422b1572023bed5d8a4` / target blob `054451b1be4f39254d56a1683cc9d1c1b5e55018`, and fix `a0e30483ab3e4aead67ecfb5c708489915e447f9` / tree `82af11ced4297818410ccf61906b703d25b69165` / target blob `95f54f2875f401afe3167c62f8c1e7799782be8c`. Both use creator blob `757b8d050d306d349822600deacb295c7a54245e`. The adapter also verifies 30 exact same-repository source blobs used for creator/effect summaries, owner/method declarations, macro mapping, key type declarations, helper APIs, and GN target membership. The request must identify `openharmony/arkcompiler_ets_runtime` and the current-component target, and the model version must equal the detector version. A matching path, function name, creator spelling, or user-declared repository by itself is insufficient. Missing or mismatched identity is `blocked` and the analyzer is not called. This explicit pair allows a research parent/fix comparison; it is not a version-general production model.

The accepted semantic subset is one exact, qualified `BuiltinsTypedArrayStubBuilder` caller with the model's exact parameter signature, one exact `NewObjectStubBuilder::NewTypedArray` creation call with the modeled arity, and the modeled `StoreTypedArrayElement` sink signature. Calls, generated control, aliases, mutations, exceptions, and loops are interpreted only by the explicit bounded IR/effect rules. Any unresolved or unsupported effect yields `unknown`/`partial`, never a safe result. Macro expansion, C++ type resolution, inheritance, overload resolution and target build flags are not inferred from spellings.

The pinned creator implementation was separately read from the fix commit's `ecmascript/compiler/new_object_stub_builder.cpp` (blob `757b8d050d306d349822600deacb295c7a54245e`). `NewObjectStubBuilder::NewTypedArray` enters its fast allocation path only when the source has no constructor, the TypedArray species protect marker is valid, and the prototype accessor has not changed; otherwise it calls `TypedArraySpeciesCreate`. The fast path allocates using `srcType` and the source typed array's metadata. This establishes the creator's source-level branch structure for the pinned history only. It does not prove how product macros/build flags resolve the guards, whether a product runtime reaches either path, or what species behavior occurs at runtime.

## Parse and identity rules

1. `SourceUnit.parse_status` remains authoritative. The research partial path may inspect a recovered function only when the function itself parses and the owner/signature resolve uniquely; it must preserve `partial` and attach `parse_dependency_contamination_unknown` and `production_runner_not_admitted`.
2. A source-level parse error cannot be repaired by a successful private probe, and no partial result is accepted by the strict adapter. Regression tests supply a blob-correct partial target with recovered AST facts and require the public research adapter to emit no findings (`blocked` / `not_analyzed`); they also verify the public registry still rejects explicit C-line selection. Production analysis requires complete AST eligibility from the shared public facts.
3. Findings and source identities remain tied to the caller's content SHA-256 and exact Git blob. Creator identity is separately bound to its pinned commit/blob. A target mismatch blocks before syntax analysis.
   Regression tests forge the shared-facts blob declaration for both target and creator independently; recomputed Git blob IDs must still cause `blocked` before analysis.
4. `candidate` means a bounded symbolic path found a differing type-token origin under the model; it is not a numeric type mismatch, runtime behavior, or security impact. `matched` means the bounded path has an equality/guard proof for that input. It does not make the component safe. Unsupported semantics are `unknown`; inability to execute the adapter is `blocked`.
