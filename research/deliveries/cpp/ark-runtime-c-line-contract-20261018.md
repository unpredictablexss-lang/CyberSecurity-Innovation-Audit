## Parse and identity rules

1. `SourceUnit.parse_status` remains authoritative. The research partial path may inspect a recovered function only when the function itself parses and the owner/signature resolve uniquely; it must preserve `partial` and attach `parse_dependency_contamination_unknown` and `production_runner_not_admitted`.
2. A source-level parse error cannot be repaired by a successful private probe, and no partial result is accepted by the strict adapter. Regression tests supply a blob-correct partial target with recovered AST facts and require the public research adapter to emit no findings (`blocked` / `not_analyzed`); they also verify the public registry still rejects explicit C-line selection. Production analysis requires complete AST eligibility from the shared public facts.
3. Findings and source identities remain tied to the caller's content SHA-256 and exact Git blob. Creator identity is separately bound to its pinned commit/blob. Wrong provenance, target path, commit, or bytes blocks before syntax analysis.
   Regression tests forge the shared-facts blob declaration for target and creator independently, supply a same-name function at an unbound path, use fixture provenance, and provide partial target bytes that disagree with the pinned blob. Adversarial recovered AST facts also claim `parse_status=complete`, substitute a target blob, and redirect/forge the creator path/blob; target or creator Git-object recomputation still blocks before syntax analysis. A blob-correct partial target remains `blocked`/`not_analyzed` in the strict adapter; the private replay labels remain explicitly `partial` and do not feed identity data back into the model.
4. `candidate` means a bounded symbolic path found a differing type-token origin under the model; it is not a numeric type mismatch, runtime behavior, or security impact. `matched` means the bounded path has an equality/guard proof for that input. It does not make the component safe. Unsupported semantics are `unknown`; inability to execute the adapter is `blocked`.

## Admission and confirmation gate

Keep `admission_status=blocked` and `execution_enabled=false` in product metadata. Before reconsidering public Runner admission, complete the exact-source adapter regression checks, resolved dependency/build-profile evidence, all control families above, a frozen algorithm, and a separately selected official component labeled blind by a reviewer who did not develop the rule. Report sample coverage, partial/blocked/unknown denominators, and root causes. Product vulnerability promotion additionally requires evidence of actual product build inclusion, runtime type behavior, reachable product entry, attacker control, feasible generation path, and concrete security impact.
