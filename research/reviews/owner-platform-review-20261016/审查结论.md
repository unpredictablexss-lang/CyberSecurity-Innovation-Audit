## 发现

### R1 / P1：新增网页测试依赖未被 Python CI 作业构建的产物

位置：`tests/test_workbench.py:103–107`；关联 `.github/workflows/ci.yml:19–40`。

`test_served_ui_to_worker_to_report_flow` 直接要求 GET `/` 返回 200。首页依赖忽略的 `web/dist`；Python CI 作业只安装 Python 依赖并执行 unittest，另一个 Web 构建 job 不共享该作业的文件系统。

复现采用 Git HEAD 导出再覆盖五个 dirty 文件的隔离副本，不删除原工作区构建物：

```bash
cd /tmp/ohscanner-review-20261016-56o3p1a2/snapshot
/home/audit/ohscanner/envs/web/bin/python -m unittest tests.test_workbench.WorkbenchTests.test_served_ui_to_worker_to_report_flow -v
```

未构建时：`AssertionError: 404 != 200`，1 项失败。隔离副本先执行 `npm run build` 后，同一测试通过。证据：`clean-ui-test.log`、`web-build.log`、`built-ui-test.log`。

建议在同一个需要首页的 CI 作业内构建前端，或把构建后 UI 集成检查独立到能获取产物的作业，并让纯 Python 回归保持独立。不要用无条件 skip 掩盖验收。

### R2 / P2：提交新任务后，旧详情刷新覆盖新任务选择

位置：`web/src/pages/Operations.tsx:16–24`。这是既有公共页面问题，本轮发现，不是声称由矩阵 payload 修复新引入。

已打开旧任务详情时，`submit` 先 `setSelected(newItem)`，随后调用闭包中的 `refresh()`；该闭包仍读到旧 `selected`，完成 `/operations/<旧ID>` 请求后再次 `setSelected(oldItem)`。新任务确实已创建，但详情会回到旧任务，容易误读本次操作的状态和结果。

使用原文件的实际表单 handler 做受控执行回放，mock React hooks/API 后记录到选择写入顺序 `[new-operation, old-operation]`，请求最终指向 `/operations/old-operation`。证据：`replay-ui.mjs`、`handler-replay-result.json`。这是 handler 级复现，不冒充真实浏览器 E2E。

建议分离队列刷新与当前详情刷新，并在异步响应落地时检查当前选中 ID，避免过期请求改写当前选择；补充“旧详情打开后创建新任务”的回归。
