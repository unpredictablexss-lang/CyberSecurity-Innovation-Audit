## Independent execution

Using Python 3.13.9 and the frozen D67 script, I replayed against the exact source checkout at commit `dd22c7cb5e5f207a6c38c50f45b7369ee8575840`, tree `e374a0d61c9ec664ddd29fc17002797828c480ee`, with the saved D50 and D68 reports. Fresh script output was structurally identical to the committed D67 JSON. It reported:

- 67 C++ units, no SHA-256 mismatches;
- D50: 57 complete, 10 partial, 1 TypeScript `not_run`;
- D68: 59 complete, 8 partial, 1 TypeScript `not_run`;
- no unnormalized per-file status mismatches.

I separately compared each unnormalized current diagnostic tuple `(kind, start_line, end_line)` and status with the 67 saved D50 rows. All 67 matched. I also compared D67's recorded D50/D68 rows to the original D50/D68 per-file records; no status, kind, or line mismatch was found. The ten D50 partial files are exactly those listed in the D67 report; their current D68 statuses are eight partial and two complete.

The D67 audit script persists current normalized and unnormalized node diagnostics in its 67-file JSON. Its `unnormalized_mismatches` accumulator, however, checks only `raw_status != D50_status`; it does not encode issue-kind/line comparisons. The report's broader status+kind+line claim is independently confirmed here, but a future audit-script revision should make that tuple comparison explicit so its stored mismatch field directly represents the full claim.
