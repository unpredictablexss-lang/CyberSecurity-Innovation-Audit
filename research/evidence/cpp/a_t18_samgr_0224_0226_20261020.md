## Scope and source binding

This review independently follows the three A0 candidates at the reported `WriteRemoteObject` sites. It uses the exact `systemabilitymgr_samgr` commit `08e2a552b839ea7727251cb9b749a5c1dd9cfeff`, whose tree is `b7a89e95be788f2f2372258e341f7be842c7826d`. The tree resolves `services/samgr/native/source/system_ability_manager_stub.cpp` to blob `ae84d998c4d90c8c08d692b9020404593b58a0cc`; its 78,212 bytes hash to SHA-256 `e82aa966b6c70278c64683b3bc4c0b236cf7550da3e65aeafc12acfa5f718433`. The commit/tree/blob/hash chain was checked against the local Git project-object mirror.

All three multi-user transaction registrations and enum values are guarded by `SUPPORT_MULTI_INSTANCE` (enum codes 45, 46 and 47; `samgr_ipc_interface_code.h:62-65`; stub registration `system_ability_manager_stub.cpp:229-245`). `OnRemoteRequest` applies the interface-token check and dispatches mapped codes (`system_ability_manager_stub.cpp:293-309`). This token check binds the interface protocol; it does not establish an authorization policy for a caller. `CheckGetSAPermission` consults `ServiceChecker` only with `WITH_SELINUX`; otherwise it returns true (`system_ability_manager_stub.cpp:47-56`).

## Status and next evidence

The original A0 rows remain `not_reproduced` / `queued_not_reproduced`; the scanner’s recorded source-file coverage remains partial (`detector_model_incomplete`).
