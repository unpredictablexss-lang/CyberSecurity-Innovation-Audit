## Remaining findings

1. **Machine-record defect:** duplicate keys listed above are an unambiguous JSON quality problem. `python` JSON parsing succeeded, but permissive parsing does not make duplicate keys safe for consumers. Markdown and JSON semantic intent matches, but the JSON cannot pass a strict uniqueness check until repaired.
2. **Source identity edge cases remain partly underspecified:** the protocol hashes source bytes and excludes duplicate snapshots, but it does not fully define treatment of submodules, symlinks, identical blobs appearing in distinct repositories, or vendored copies. These cases need deterministic inclusion/exclusion and deduplication rules in the frame policy before selection. This preserves a gap from the prior review.
3. **Execution gates are still open by design:** owner approval, source inventory/frame and cohort, overlap ledger, scanner hashes, advisory snapshots/hashes, reviewer assignments, blind storage, and frozen planning simulation do not exist in this protocol-only package. The execution task accurately says `not started`; these are not evidence of a completed evaluation.
