# A-NULL 独立盲审协议

## 盲审边界

复核者只使用本目录的 `blind_review_queue.csv`、该队列所列固定 commit 的源码和本协议。标签提交并冻结前，不查看 `coordinator/review_key.csv`、扫描器规则/消息/分层、抽样权重、候选总体或开发者预期。不得通过 `review_sample_id` 查询检测器输出。完成后保留原 CSV 字段与顺序，记录交回文件 SHA-256、复核者 ID 和日期；由协调员冻结标签后再解盲合并。

先在对应 repository/commit 下核对 `source_sha256`。如果仓库提交或源码哈希无法取得，不推测标签，使用 `not_testable` 并具体说明缺失证据。队列中的 `source_context` 只用于定位；应查看完整函数、相关类型/成员声明，以及有必要且可取得的调用者和被调函数。

## 逐条检查

1. 确认记录位置实际存在指针、智能指针、成员访问、解引用、下标或间接调用等相关操作；记录实际语义，不能仅因局部文本形状认定问题。
2. 追踪潜在空值来源到该操作：检查初始化、赋值/别名重绑、参数约束、返回值契约、错误分支、早返回、短路条件和覆盖该使用点的空值检查。列出支持结论的源码位置。
3. 对成员/全局状态、宏、模板、异常、跨函数别名、动态分派或构建宏有影响但无法核实的路径，明确记为 unknown。不得把词法上的 guard、源码注释或名称猜测当成完整 CFG 支配、调用可达性或安全证明。
4. 标签描述的是固定源码中的 NULL 使用形状及其可验证性，不等同于可利用漏洞、攻击者控制、产品可达性、崩溃或 CIA 影响已证实。将这些影响另写在理由的 remaining unknown 中。

## 标签

| `reviewer_disposition` | 使用条件 |
|---|---|
| `confirmed` | 固定源码中存在实际 NULL 可达的解引用/访问路径，且已记录空值来源与可行路径证据。该标签只确认源码级问题形状，不代表产品影响或可利用性已确认。 |
| `safe_or_fixed` | 候选操作存在，但源码证据证明相关路径不可达，或所有到达该使用点的路径均由有效非空约束/检查保护。写出覆盖该使用点的条件及行号；不能仅凭局部 if 文本判断。 |
| `known_false_positive` | 语法形状与真实语义不符，例如实际不是指针解引用、接收者/操作对象识别错误，或候选所称 source/sink 关系不存在。说明真实语义。 |
| `not_reproduced` | 固定 commit、文件、行或哈希经核验后，记录的源码位置/观察无法复现或身份字段具体不一致。说明差异；不得用它掩盖仅缺少构建上下文的情况。 |
| `not_testable` | 缺少必要的源码版本、宏/模板实例、类型/调用者/依赖实现或可信构建配置，无法对候选路径作有依据的判断。列出缺失对象。 |
| `unknown` | 有可检查证据但互相矛盾或不足以归入上述标签。写清冲突和仍未知的事实；明确环境缺失优先使用 `not_testable`。 |

`confidence` 填 `high`、`medium` 或 `low`，表示对标签判断的把握，不是严重度。`reviewer_rationale` 至少说明实际操作、NULL 来源/约束、控制路径和 remaining unknown。`evidence_reference` 使用 `path:line` 或可定位的构建/契约文档。

## 交回

保留全部 160 个 `review_sample_id`、全部原列和顺序；只填写 `reviewer_disposition`、`reviewer_rationale`、`evidence_reference`、`confidence`、`reviewer_id`。不去重、不重采、不修改源码身份字段，不填写协调员专用字段。完整队列交回后计算 SHA-256，并将该值作为冻结锁传给 `merge_null_candidate_review.py`。合并结果只写入 coordinator 目录。该程序校验提交完整性和映射完整性，不验证复核者身份或标签正确性。

本 pilot 对应 403,360 条原始观察的具名 provisional run；它不代表未绑定的 546,559 总体。不得据此报告该未绑定总体的 Precision/Recall。
