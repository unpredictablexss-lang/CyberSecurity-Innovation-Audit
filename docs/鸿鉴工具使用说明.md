# 《鸿鉴工具使用说明》


本说明书面向鸿鉴工作台使用人员，按照“仓库接入—任务创建—结果复核—验证与报告”的业务流程组织。各步骤标明页面入口、关键输入项、操作动作及结果检查位置；截图用于对应说明当前界面。

## 先选一种使用方式

第一次使用时，先完成第1节的工作台访问和第2节的仓库登记。为比较三种方式，建议每次使用同一个仓库、同一个 Commit 和同一组纳入路径；这样三份任务结果对应同一份源码。

开始前确认：智能审计需要在“系统设置”中配置可用的模型服务。只做静态扫描不需要模型服务。智能审计创建时会显示授权预览；仔细核对后再确认。

- **方式一｜静态扫描 + 人工复核：**只使用检测器；到“任务中心”看扫描，到“风险中心”看候选并记录复核。
- **方式二｜AI 初判 + 手动授权深入调查：**创建时授权初判；看完初判后，自己逐条或批量授权深入调查；到“任务中心”查看操作和结果。
- **方式三｜一键智能审计：**创建时一次授权；系统自动进行初判和符合策略的深入调查；到“任务中心”查看进度，到“风险中心”查看候选。

### 方式一：静态扫描 + 人工复核

**演示目标：**只使用本地检测器生成候选，然后由使用者查看源码证据并登记判断。整个流程不调用 AI。

1. 点击左上方“新建审计”，进入“仓库审计”。选择仓库、分支或 Commit，并确认纳入路径。画面会显示本次固定的仓库版本和扫描范围（图5）。
2. 在审计方式处选择“静态审计”，点击“开始静态审计”。系统创建扫描任务；页面转到任务记录或显示创建成功。
3. 打开“任务中心”，点开刚创建的任务。等状态完成后，核对 Commit 和文件覆盖；任务详情会显示扫描状态、解析情况和报告入口（图9–图11）。
4. 打开“风险中心”，按仓库和 Commit 找到本次候选。点击候选查看规则、文件、行号及源码片段（图12、图13）。
5. 在候选详情的“添加人工复核”区域选择复核状态，填写复核人和依据，点击“保存追加记录”。保存后，复核记录会出现在候选详情和列表中（图14、图15）。

**演示完成后应看到：**一条已完成的静态扫描任务、对应的候选源码证据，以及已保存的人工复核记录。

### 方式二：静态扫描 + AI 初判 + 手动授权深入调查

**演示目标：**先让 AI 对筛选出的候选做初步分析，再由使用者选择单个候选或符合条件的候选组，检查深入调查范围并另行授权。

1. 点击“新建审计”→“仓库审计”，选择仓库、Commit 和纳入路径；在审计方式处选择“智能审计”。
2. 展开“高级范围与调查设置”，取消勾选“允许深入追查”。点击“预览授权并开始智能审计”。
3. 在“智能审计：确认模型外发范围”窗口核对模型、固定来源、候选上限和源码范围。确认无误后点击“同意范围并开始智能审计”。系统先做静态扫描，再按本地排序结果对授权范围内的候选进行 AI 初判。对应任务入口见图5，任务进度见图10、图11。
4. 打开“任务中心”→“区间与验证操作”，找到状态已完成的“批量 AI 初步分析”并点击“查看”。在详情表中查看每组的“模型建议”和状态；只对建议“继续调查”的候选执行下一步。
5. 逐条深入调查：在目标候选所在行点击“AI 深入追查（查相关链）·重新预览授权”。要一次处理全部符合条件的候选组，点击详情上方的“预览并批量授权 AI 深入追查”。
6. 在弹出的范围预览中核对候选、仓库 Commit、源码范围和允许使用的工具。逐条授权时勾选确认框并点击“确认授权并排队”；批量授权时检查清单全部内容、勾选确认框并点击“确认清单并排队”。
7. 在“任务中心”→“区间与验证操作”打开新建的“AI 深入追查”记录，查看执行状态和结果。候选源码证据的页面示例见图13。

**演示完成后应看到：**静态扫描结果、AI 初判操作，以及仅对你授权的候选生成的 AI 深入调查操作。没有选择或不符合条件的候选仍保留在任务结果中。

### 方式三：一键智能审计

**演示目标：**创建任务时确认一次授权。系统完成静态扫描和 AI 初判后，按策略自动对符合条件的候选继续深入调查。

1. 点击“新建审计”→“仓库审计”，选择仓库、Commit 和纳入路径；审计方式选“智能审计”。
2. 展开“高级范围与调查设置”，确认“允许深入追查”保持勾选。点击“预览授权并开始智能审计”。
3. 在“智能审计：确认模型外发范围”窗口核对模型、固定来源、候选上限和源码范围；确认后点击“同意范围并开始智能审计”。这项授权同时覆盖 AI 初判以及满足策略条件的 AI 深入调查。
4. 打开“任务中心”中的任务详情，查看“静态扫描”“AI 初步分析”和“AI 深入追查”进度。处理完成后，在“风险中心”查看候选和证据，并从报告中心打开扫描报告（图9–图12、图22）。

**演示完成后应看到：**同一任务关联的静态扫描报告、AI 初判结果和符合策略条件的深入调查结果。未进入后续阶段的候选仍可在任务详情中查看。

### 三种方式的结果对照

| 使用方式 | 深入调查由谁决定 | 最终结果 |
|---|---|---|
| 静态扫描 + 人工复核 | 不运行 AI；使用者查看并记录判断 | 扫描报告、源码候选、人工复核记录 |
| AI 初判 + 手动授权深入调查 | 使用者读完初判后逐条或批量授权 | 扫描报告、AI 初判操作、获授权的深入调查操作 |
| 一键智能审计 | 系统按任务策略自动继续调查 | 扫描报告、AI 初判和符合条件的深入调查结果 |

## 二、仓库登记与版本固定

仓库登记建立工作台与源码之间的可追溯关联。在线同步适用于从公开仓库目录检索项目并获取指定分支或提交；本地登记适用于已位于服务端磁盘上的 Git 仓库。登记后，工作台读取仓库引用和提交信息，供任务配置选择。任务绑定的 Commit 与 Git Tree 构成扫描快照标识，使后续候选、复核记录和报告能够对应到同一份源码状态。对需要复现的任务，应在创建前确认目标引用解析到预期提交。

## 三、扫描范围选择与任务创建

任务创建分两步：先选扫描范围，再选审计方式。仓库快照扫描一个固定版本；时间增量扫描指定时间内的提交；跨版本分析比较基准版本和目标版本。静态审计只运行本地检测器，生成候选供人工复核。智能审计在静态扫描后自动进行 AI 初判；“允许深入追查”保持勾选时，符合策略条件的候选会继续进入 AI 深入追查。需要自己挑选候选再授权深查时，按本页开头的方式二操作。

| 步骤 | 操作（点击位置/输入项） | 页面输出/检查结果 | 对应截图 |
|---|---|---|---|
| 3-1 | 进入“仓库审计”，选择仓库、分支/Tag/Commit 及扫描方式，按需设置纳入路径 | 任务配置区显示固定仓库版本、审计方式和扫描范围 | 图6 |
| 3-2 | 进入“时间增量扫描”，设置起止时间及时区，点击“预览时间区间”并核对提交，再固定区间并创建任务 | 预览列出纳入区间的提交；确认后生成记录固定时间窗口的任务 | 图7 |
| 3-3 | 进入“跨版本安全分析”，分别选择基准版本和目标版本并创建任务 | 任务记录比较的两个版本端点及对应 Commit | 图8 |
| 3-4 | 按需求选择静态审计或智能审计后创建任务 | 静态审计生成本地扫描任务；智能审计按已配置流程启动后续研判 | 图6–图8 |

## 五、风险候选查看与人工复核记录

## 六、智能调查与知识库引用核对

智能调查围绕已选候选生成限定范围的研判请求。提交前的预览用于检查本次调查所依据的候选、源码片段、问题描述以及检索到的知识库资料；确认范围后再创建调查记录。任务详情记录调查关联的扫描版本和执行范围，结果中的知识库引用则保留资料路径、行区间、摘要和内容哈希等来源信息。展开引用条目可查看结构化内容及其来源标识，便于从研判结论回到原始知识资料核对。

|---|---|---|---|
| 6-1 | 在候选详情选择“智能调查”或“模型辅助调查”，填写问题并选择调查类型，点击“预览本次将发送的数据” | 预览窗口列出候选范围、源码片段和知识库参考资料 | 图16、图18 |
| 6-2 | 核对候选、来源路径、行范围与资料片段后提交调查请求，再到任务中心查看记录 | 系统创建调查记录或任务；详情页展示任务状态、固定版本及执行范围 | 图17 |

## 九、常用操作与问题定位

系统设置提供仓库与源码管理、审计策略、Agent/LLM 和 Worker 等配置状态入口。策略与服务状态会影响仓库同步、任务调度及智能调查流程，创建任务前可据此确认当前工作台使用的配置。常见问题可沿操作链路定位：仓库不可选时回到登记列表检查仓库状态；版本检索无结果时确认引用名称或使用完整 Commit SHA；解析范围不完整时从任务详情查看覆盖与执行记录；报告下载后可通过浏览器下载列表打开对应文件。刷新操作重新读取当前页面数据，不改变已固定的任务范围。
