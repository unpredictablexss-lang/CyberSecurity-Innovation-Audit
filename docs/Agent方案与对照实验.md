# Agent 工作流程与实验评价

模型辅助调查以静态候选和固定源码为起点，补充证据及调查建议。本文区分当前实现、实验设计和实验结果；不将设计目标写成已测性能。

## 当前工作流程

静态检测产生候选及证据义务后，系统根据源码身份整理候选组，并提供 AI 初步分析和深入追查。深入调查按需调用固定版本的只读源码工具，组织引用、查找反证并输出结构化结果。

单轮模型复核和工具型 Agent 仍有各自入口与兼容流程。渐进式快筛、深入追查和旧自动分诊的预算语义不完全相同，详见[架构与公共协议](架构与公共协议.md)。

| 部分 | 当前职责 |
|---|---|
| 自研静态检测 | 在明确的语言、规则与固定版本条件下提出候选 |
| 分组与优先级 | 整理重复观察，决定后续调查顺序，保留全部原始候选 |
| AI 初步分析 | 对授权的候选或候选组作初步研判，给出是否值得深入调查的建议 |
| 工具型深入追查 | 读取受限固定源码、符号与历史线索，查找支持和反证，整理未解决义务 |
| 服务端校验 | 核对结构、源码绑定、证据引用及授权范围，记录失败与局限 |
| 人工复核及隔离测试 | 判断引用语义、入口、权限、触发条件、真实影响及修复效果 |

AI 结果不自动覆盖人工记录，也不把候选升级为产品漏洞。引用存在、源码链连贯与实际可利用性须分别评价。

## 本地参考检索

`src/workbench/agent_knowledge.py` 使用 BM25，在仓库内结项实验材料包中检索历史 CVE/PoC 参考。已接入的候选调查预览最多选择四段，每段最多 1,200 字符，记录材料路径、行号及哈希，并纳入授权核验。

参考片段是背景资料，不能作为当前目标源码事实的替代证据。无匹配不伪造参考；语料摘要变化须重新核对预览。该实现不意味着所有渐进式或批量入口都已接入检索，也不证明检索改善了模型准确率。

## 对照实验设计

主实验固定同一批静态候选，比较调查能力：

| 组别 | 方法 | 主要观察 |
|---|---|---|
| R0 | 静态结果 + 统一标准人工复核 | 基础证据质量、人工耗时 |
| R1 | 同候选 + 单轮模型分析 | 解释、错误引用、研判收益和费用 |
| R2 | 同候选 + 只读工具型 Agent | 新增有效证据、反证质量、未知项和复核成本 |

三组固定仓库、提交、路径、检测器、初始证据及评判标准。模型、提示词、工具、可见源码及预算不同须单列，不能把更多上下文或更多算力混作方法收益。

主动探索新候选与对已有候选调查是两种实验问题；若比较静态发现、模型主动发现和混合发现，应使用单独的数据与统计口径，不直接套用 R0/R1/R2 的分母。

## 数据与真值

- 开发、调参与冻结测试集分开，按根因或修复家族划分，控制同源变体泄漏。
- 准备有问题、已修复、安全及无关对照，绑定仓库、父提交/修复提交、blob、源码摘要和运行条件。
- 独立复核源码及适用的动态证据，再建立标签。模型自己的判断不能作为真值。
- 公开 CVE 可能已进入模型训练；历史补丁命中不能证明零样本泛化。
- 解析失败、版本不适用和缺少构建上下文保留未知或排除理由，不能强行计作正确识别。

## 指标与结果报告

| 指标 | 必要条件 |
|---|---|
| Precision / Recall、TP / FP / FN | 适用的独立真值集，以根因或明确评测单元统计 |
| 分析覆盖 | 同时报告完整、部分、未分析及失败范围 |
| 证据质量 | 独立确认的新事实、错误/缺失引用、反证与义务完成情况 |
| 人工成本 | 统一复核标准、记录时间，尽可能盲化评阅 |
| 运行成本 | 实际墙钟、RSS、Token、工具调用和费用；缺失计量保持未知 |
| 可重复性 | 固定版本、配置、采样、重复次数及全部运行记录 |

回归测试通过说明实现路径满足测试条件，不等于漏洞检测准确率。组件 Harness 触发、历史 CVE 对照和真实产品漏洞确认分别报告。零候选、模型同意或有限样本不能支持“零误报漏报”。

实验记录应包含清单、精确命令、提交/模型/提示词/工具版本、原始日志、摘要、结果表及限制。材料入口为[benchmarks](../benchmarks/)与[research](../research/)；其中历史结果仅适用于原记录的版本和环境，本次文档整理未重新运行模型效果实验。
