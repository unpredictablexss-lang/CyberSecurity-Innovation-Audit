# Agent 方案与可复核对照实验

2026-10-14 方案基线（历史记录）。本文前半部分记录当时的设计设想，不代表当前实现；当前隔离分支实现与验收状态见下方“2026-10-17 实现检查点”。截至 2026-10-18，真实模型调用和效果评测仍未进行。
不训练基础大模型、不把采购 GPU 当前置条件；先用可替换 API 后端，
需要离线/隐私/成本约束时再评估本地模型。模型缺席时核心仍能运行。

## Agent 的具体作用

2026-10-14 方案基线：输入固定候选、来源证据和义务，按固定顺序调用只读工具；当时尚未形成模型驱动的工具循环。当前实现已增加 R1 单轮模型复核和 R2 有界只读工具 Agent（见下方检查点），模型不能自行扩大到新 candidate；后续主动发现仍是独立实验方向。
不能直接改原始扫描结果、Git 对象或确认状态。

方案基线里的工具范围：固定源码摘录、EvidenceObligation 查询、固定提交 Git 历史和 Detector 已记录的符号/parse 摘要。当前实现的工具范围及其限制见下方检查点；仍未实现通用调用图搜索、历史补丁检索、模型选择器或多 Agent 编排。AST 是有限程序事实；partial、间接调用和缺编译上下文继续 unknown。
新增验证只能提交结构化计划，由独立验证服务在授权隔离环境执行。

每次记录 model/provider/version、提示词/工具版本、参数/采样、
输入上下文与 hash、工具调用/返回证据 ID、Token/费用/耗时、失败/重试与最终假设。
源码注释/README/提交消息均是不可信数据，不执行其中指令。
不赋无限 Shell、任意联网和 Git 写权限；发送源码到第三方前先确定数据处理约束。

## 主实验：调查能力，固定同一批静态候选

| 组 | 方法 | 主要问题 |
|---|---|---|
| R0 | 纯 OHScanner + 同标准人工审查 | 基础根因区分与人工成本 |
| R1 | 同候选 + 单轮 LLM review | 单轮解释的收益/幻觉/成本 |
| R2 | 同候选 + 有界工具型 Agent | 多轮取证是否补齐有效事实、减少人工工作 |

三组固定 target/commit/scope/Detector/初始证据、工具返回口径和判定标准。
R2 增加工具预算要显式报告；不要把更多算力偷偷当方法增益。当前只读操作轨迹可作为 R2 工具执行记录的基础，但尚未形成模型实验。
人工用时单独测、评审盲化，模型自评不作为真值。
消融：去掉 AST 工具、去掉历史补丁工具、只允许一轮；
失败调用、超预算和 unknown 全计入，不挑最好的一次。

## 补充实验：发现策略

| 组 | 候选入口 |
|---|---|
| D0 | 自研静态 |
| D1 | 定向 LLM 主动探索 |
| D2 | 两路混合，统一来源绑定与归并 |

与 R 实验分开，不比较“同一候选调查”与“全库主动读”却用同一分母。
明确每组可见文件/函数、读到的字节、上下文覆盖、Token/工具预算与迭代次数。
先选一个窄漏洞家族和可复核组件，不宣称模型通读整个 OpenHarmony。

## 数据集与真值

开发集、调参集、冻结 holdout 分开；按根因/补丁家族拆分，避免同一漏洞的变体泄漏。
至少有 vulnerable/fixed/safe/unrelated；每项固定 repo/parent/fix/tree/blob/source hash、
profile、入口/条件、ground truth 来源和排除原因。
公开 CVE 可能进入模型训练，披露污染风险；用未见变体/不同组件做补充，不能保证无污染。

ground truth 由独立源码复核/受控运行证据建立。只绑定了补丁来源，不等于已证明产品级漏洞。
跨工具比较使用相同可分析单位/构建上下文，缺 include/解析失败为 unknown，不强判 miss。
外部 Semgrep/CodeQL/Joern/Clang/Infer 等为离线基线，不成为产品 Detector 的隐藏依赖。

## 指标与报告

- 按独立根因统计 TP/FP/FN，避免多行告警当多个漏洞。
- 在可支持真值的样本上报 Precision/Recall、各子类召回、fixed/safe 误报与样本量。
- 单列文件/语义覆盖、partial/failed/unknown、证据义务满足情况。
- 独立确认的新事实比例、缺失/错误引用、人工复核耗时、可重现性。
- wall、实际测得 RSS、Token、费用、工具调用数/失败数。
- 采用冻结重复次数和随机种子/采样设置，报告全部运行及方差/区间，不能只报最佳。

0 findings 不证明安全，模型同意不证明漏洞；有限样本不支持“零误报漏报”。
最终实验包包含 manifest、exact argv、配置/模型/提示版本、原始日志、hash、结果表和限制。
截至 2026-10-18，R1/R2 接口、工具和预算控制已有实现，但没有真实模型调用或效果数据，主实验 R0/R1/R2 仍未启动。先冻结同一批候选与人工真值，再比较静态人工基线、R1 和 R2；之后才扩 D1/D2，避免同时改变算法、数据、工具和预算。


## 2026-10-17 实现检查点：受限 Agent 原型

本段描述 work/agent-llm-20261017 的未合并实现，不能据此说 18775/8765 正在运行该版本。面板现在提供 R1 单轮模型复核与 R2 有界工具 Agent 两种模式，均固定同一个候选来源与分诊 schema。

- 新增 GET /api/v1/agent/status、POST /api/v1/operations/agent-investigations 和操作类型 agent_investigation。只有已完成扫描且报告完整的单个候选可以排队；作业固定绑定 repo/commit/tree、report hash、candidate/source hash。执行复用现有隔离 operation child worker，支持取消和硬超时。
- 首个 Provider 是 OpenAI Responses API 兼容接口。只从 Worker 进程环境读取 OHSCANNER_LLM_BASE_URL、OHSCANNER_LLM_MODEL、OHSCANNER_LLM_API_KEY；不保存或返回 API key。端点要求 HTTPS、默认 443、无 URL 凭据/query/fragment。模型或端点在入队后变化时任务失败关闭。
- UI 在“候选调查”下增加 LLM Agent 标签，显示配置的目标 hostname/model，并要求逐次勾选源码外发同意。表单锁定于页面传入的已完成 job/candidate 上下文；没有这两个 ID 时不可提交。面板表述为“候选/unknown 建议”，不自动改案例审核或漏洞状态。
- 调查表单可选关联案例；服务端只接受已关联同一 job/candidate 的案例，拒绝错绑。案例 JSON/Markdown 导出摘要包含 Agent 分诊、证据引用、未知项、预算、来源绑定与限制，并显式标注为非漏洞确认；不改写原始发现或人工审核。
- 开始调查前先展示固定候选的实际上下文、源码摘录、证据义务、模型目的地、工具可能追加读取的固定提交范围及预算。用户授权绑定到预览 SHA-256；模式、预算、模型或候选变化会使预览过期，API 拒绝旧指纹。
- 外发前对初始上下文和每次工具返回执行本地凭据样式脱敏（私钥块、常见云/API token、Bearer token、凭据赋值）；用户预览显示类别，授权哈希绑定脱敏后的实际内容。该规则集是防误发的第一道过滤，不是完整 DLP，也不能保证检出所有秘密。
- Provider usage 缺失时，聚合 Token 总量导出为 unknown/null，同时保留已观测调用小计；不得将缺失计量显示为 0。
- 工具仅有固定候选源码摘录、证据义务、固定提交历史、受限精确符号文本搜索；所有工具结果在写入调用轨迹或发送给模型前先脱敏；禁止模型提供路径/命令。每次单一工具调用，R1 单轮一次调用且不开放工具；R2 最大 6 步。两者均配置总输入预算按完整 UTF-8 请求字节做保守预检并由 Provider usage 后验校验，单次/累计输出 token 和 Worker wall-time 预算。Responses 请求设 store=false。结果保留请求/响应哈希、工具证据 ID/hash、模型 usage；费用暂记 unknown。
- 每条支持陈述需提供证据 ID 和至少 8 字符的逐字引句；服务端验证引句确实存在于对应哈希绑定的初始上下文或工具返回中，结果与案例报告展示引句。该校验只证明引用来源存在，不证明模型从原文得出的推理成立。
- POST /operations/{id}/agent-reviews 追加人工评价事件并绑定 Agent 结果 SHA-256，记录分诊实用性、引文准确性、复核耗时、遗漏证据和更正意见；不改候选、案件判定或漏洞状态。GET /agent/evaluation-summary 按模式、模型及提示/工具版本汇总这些自报反馈，并明确不是漏洞真值、Precision 或 Recall。案例报告一并包含反馈记录。
- 最终对象需匹配严格 JSON Schema，支持声明必须引用本次工具证据；assessment 只能是 likely_true_positive、likely_false_positive、needs_more_evidence 或 unknown，属于模型分诊倾向。无论模型文本如何，operation 结果固定 vulnerability_state=candidate 且 validated_vulnerability=0。原始扫描结果和人工案例评估不被 Agent 改写。
- 该实现有 mocked provider 测试；本轮没有 API key、没有真实模型请求、没有产品样本人工真值集，也没有 R0/R1/R2 对照结果。因此只完成了“可实验的第一版接口/工具层”，不等于 Agent 效果已验证，更不能写作“80%完成”或模型已能确认漏洞。
