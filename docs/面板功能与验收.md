# 面板功能与产品验收

更新：2026-10-16。单用户形态为 Windows 浏览器 + WSL2；React/TypeScript/Ant Design/Monaco、FastAPI、SQLite 和独立 Worker，V1 不依赖 LLM、GPU、开发板或公网服务。

## 何时读取

修改 Workbench API、Worker、SQLite、React 面板、浏览器验收或报告导出时读取。CLI/检测器算法与公共 schema 规则仍见架构文档。

## 当前已实现

| 页面 | 实际能力 | 不应误解为 |
|---|---|---|
| 概览 | 仓库、任务、Catalog、最近扫描 | 漏洞准确率 |
| 仓库与版本 | 登记允许根目录内 Git，选择 ref/full SHA | 自动 clone 或官方身份 |
| 新建审计 | 固定 commit/tree、include、Detector、预算 | 全 OpenHarmony 无限扫描 |
| 任务详情 | 阶段、日志、候选、覆盖、取消/按原 SHA 重试 | 精确百分比或每插件超时 |
| 固定源码/候选 | blob/hash 核验、义务、review | 实时工作区或完整路径证明 |
| 聚类/案例 | 重复观察分组、人工关联候选 | 自动根因归并或确认 |
| 证据/导出 | 源码摘录、JSON/MD、manifest、审计包 | 运行时验证或自动确认 |

追加 review 使用 expected_id 防冲突。候选、人工案例、confirmed/reportable 三数分开，当前没有自动确认服务。

## 三种审计对象

- A 快照：仓库 + 固定 SHA + scope + Detector → 覆盖/候选/报告，已实现。
- B 区间：双 SHA 或 committer-date+时区 → 端点扫描、拓扑跨度、候选比较，影响仍 unknown。
- C 版本矩阵：案例 + 多个固定 SHA → 观察差异和证据链接，affected/fixed/not_present 必须另有证据。

发现策略 static/LLM exploration/hybrid 是独立选项，后两者尚未实现。Agent 是候选调查侧栏，不是无证据聊天首页。IPC/接口 draft 固定 `draft_only`，不能修改候选、review 或确认状态。

## 验收路径

真实仓库登记 → 选择固定版本 → 提交任务 → Worker 完成 → 明示 partial/unknown → 核验固定源码 → 保存 review/摘录 → 关联案例 → 导出审计包 → 重启恢复。

保持 2026-10-15 浏览器全链路回归；另补公网 Git、真实产品组件和动态验证。服务只监听 loopback，无多人身份/公网部署验收。SSE、热更新和 PDF 不是首版必须。
