## 2026-10-21 AI 源码调查高可信候选展示

风险列表把严重程度、可信度和漏洞状态分开：例如“高危 · 高可信候选 · 待人工复核”。智能调查只有在候选、报告、固定 commit 和源码哈希完全对应，结构化结论通过校验、至少一项源码义务有支持性证据且存在可定位的文件/行号引文时，才能把候选排到“高可信”；出现源码反证、绑定不一致或缺少行号证据时继续留在待验证。此门槛刻意用于复核优先级，不表示每条利用链已闭环。

用户打开候选详情后，顶部显示一条 AI 摘要，并可点击文件与行号跳到固定源码；同一处明确显示漏洞状态仍为“候选”。界面说明引文逐字匹配已核对，但主张是否被源码语义支持、产品入口是否可达和实际影响仍需人工复核。严重程度来自风险本身，可信度说明证据支撑，二者不互相替代。AI 结论不会把 `candidate` 改成 `confirmed`，也不会改写 `validated_vulnerability`。

验收：风险层级版本 `ohscanner-evidence-risk-tiers-0.2.0`；两项后端专项测试通过，覆盖 AI 支持性证据进入复核队列但仍为候选，以及较新的不确定结果覆盖旧的支持性结果。Owner 集成模块 22/23 通过；唯一失败是既有 C 检测器版本测试固定期待 `0.21.0`、当前实际为 `0.21.17`。Web 69/69、TypeScript 检查和 Windows Node 生产构建通过。没有调用真实 Provider、创建扫描、执行动态 PoC 或修改 8765 服务；没有进行像素级浏览器验收。

## 2026-10-19 智能安全审计工作流与仓库路径边界

新建仓库审计默认“智能安全审计（标准研判）”，也可明确选“仅静态扫描”。预览同时绑定扫描计划和流程模式；创建任务时后端重算两项摘要，模式或静态输入变化会拒绝过期预览。默认不自动外发；明确选择任务级自动研判授权时，静态扫描完成后最多排队 5 条单轮 R1，并在页面预览 Provider、固定源码种类、范围、脱敏策略与 Token/请求/时间预算。人工另行发起的候选批次仍逐候选预览授权。授权预览可选 R1 候选上限 1–5，并可另选 R2 上限 0–5（不得超过 R1）；R2 默认关闭。R2 只在 R1 完成、high/critical 候选仍有未解决固定源码义务时排队，并复查 R1 结果哈希和来源绑定。R2 工具、来源范围、每候选模型/请求/token/时间上限均出现在授权披露中。任务授权写入 SQLite 并可撤销；重启后 R2 转移幂等。模型输出不会改变候选或确认状态。瞬时 HTTP 429/5xx 最多重试一次，连接/超时未知结果不重试；费用为估算，Provider 账单不能硬限制。

任务详情新增模型研判进度，状态只关联当前任务和当前报告哈希；解析覆盖、候选观测、候选分组、人工确认分别呈现。无模型配置不会阻止静态扫描；历史任务没有记录模式时显示兼容说明。操作页的仓库选择改用不含路径的普通列表；仅“设置 → 仓库与源码管理”读取路径、可信根目录状态和仓库数。健康接口只公开根目录数量。

本轮协议字段为 audit_mode、workflow_sha256 和 expected_workflow_sha256；路径视图接口为 /api/v1/repositories/list、/api/v1/repositories/managed、/api/v1/repositories/roots；任务研判状态为 /api/v1/scans/{id}/triage。代码和回归验收状态记录在 [项目现状与下一步](项目现状与下一步.md)。全量 Python 回归 1331 项中 1323 通过、8 项跳过；前端 40/40、TypeScript 检查、Linux Node 22 生产构建、compileall、迁移并发专项与 git diff --check 通过。隔离浏览器使用临时数据和合成仓库确认 R1/R2 授权控件及名额输入；接口/队列边界另由合成集成测试覆盖。真实模型调用、全量扫描、动态验证或产品漏洞确认未完成。

## 2026-10-19 设置页多源码根目录

设置页允许管理员添加带别名的服务端目录；添加后可立即按 stable root_id 执行限额发现、登记仓库和审计。页面会说明目录授权范围，路径只在设置管理界面出现。移除托管根目录会停用其下的仓库记录并保留历史任务快照；仓库搬家后需在新位置重新登记，旧记录不会静默改绑。

服务端将授权保存在 OHSCANNER_DATA/managed-source-roots.json，0600 权限并原子更新，扫描/操作 worker 每次校验时动态读取。路径必须是无符号链接、非挂载点、非工作台数据区域、非组/全员可写的独立目录；服务以设备号和 inode 绑定根目录身份，并限制发现预算。此管理功能仅扩展本地允许读取的目录，不代表仓库官方身份、可信内容或扫描安全，也不执行仓库脚本或隐式联网。

验收：新增/移除/路径身份变化/移动后重新登记等服务端回归覆盖；8765 设置页实测返回 5 个部署根目录，根目录状态接口耗时约 0.03 秒。真实浏览器确认新增目录表单、授权提示、按 root_id 的发现入口和可用性表格加载。没有在生产数据中实际添加目录或创建扫描任务。全量 Python 回归 1324 项通过、8 项跳过（随后性能修正另以 17 项仓库管理测试复验）；前端 40/40、TypeScript 检查和生产构建通过。删除或路径身份变化后仓库变为不可用，历史任务不改写。
