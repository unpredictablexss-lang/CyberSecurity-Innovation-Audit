# 面板功能与产品验收

更新：2026-10-14。Windows 浏览器 + WSL2 为当前单用户运行形态。
React/TypeScript/Ant Design/Monaco，本地构建；FastAPI 同源服务 + SQLite + 独立 Worker。
V1 不依赖 LLM、GPU、开发板或公网服务器。

## 当前已实现

| 页面 | 实际能力 | 不应误解为 |
|---|---|---|
| 概览 | 真实仓库、任务、Catalog 数及最近扫描 | 漏洞准确率或模型自评 |
| 仓库与版本 | 登记允许根目录内已有 Git；本地 refs/full SHA 选择 | 已验证官方身份或自动 clone |
| 新建审计 | 固定 commit/tree、include、Detector、时间/内存预算 | 全 OpenHarmony 无限完整扫描 |
| 任务详情 | 阶段、日志、候选分页、覆盖、取消/按原 SHA 重试 | 精确百分比或每插件独立超时 |
| 固定源码/候选 | Git blob/hash 核验、定位、义务、复核历史 | 工作区实时文件或完整路径证明 |
| 候选聚类 | 同快照/Detector版本/规则/文件/符号/hash 的重复观察分组；可展开原始候选 | 根因归并、准确率或漏洞确认 |
| 调查案例 | 人工关联多个候选，追加关系依据 | 已自动证明同一漏洞根因 |
| 证据/导出 | 固定源码摘录、原 JSON/MD、manifest、人工审计包 | 运行时验证或自动漏洞确认 |
| 能力页 | 已有/未实现功能开关 | 空菜单代表能力已完成 |

追加复核保留历史并用 expected_id 检查冲突。源码摘录服务器读取本次范围内固定对象，
绑定 blob/source/excerpt/report hash；人工说明不替代程序事实。
候选、人工案例、确认漏洞三数分开。当前没有 confirmed/reportable 自动确认服务。

## 仓库与三种审计对象

| 模式 | 最终交互与后端要求 | 状态 |
|---|---|---|
| A 快照 | 仓库 + ref/SHA + scope + Detector → 冻结快照 → 覆盖/候选/报告 | 已实现 |
| B 区间 | 两 SHA 或 committer-date+时区 → 固定端点扫描、拓扑跨度与候选对比 | 浏览器全链路已验收；影响仍 unknown |
| C 版本矩阵 | 案例 + 多个固定 SHA → 候选观察差异与证据链接 | 浏览器全链路已验收；affected/fixed/not_present 仍 unknown |

B 不默认逐 commit 全扫，先端点 + 变更上下文；发现时间不等于引入时间。
C 的 affected/fixed/not_present/unknown 需要对应证据；文本 diff 只能给线索。
多仓产品版本必须使用每组件实际 SHA，不给所有组件套一个 commit。

发现策略 static / LLM exploration / hybrid 是独立选项，后两者尚未实现。
Agent 是候选调查侧栏与轨迹，不做一个脱离证据的聊天首页。

## IPC/接口调查双层 API

候选详情现提供只读 investigation 事实包、append-only drafts 和 `investigation.json` /
`investigation.md` 导出。事实包中的机械哈希门与语义义务分栏展示；草稿固定为 `draft_only`，
不改变候选/复核/确认数。当前先验收 API、持久化和导出，候选侧栏 UI 草案编辑器仍待接入。

## 验收路径

真实已有仓库 → 选择固定版本 → 提交任务 → Worker 完成 →
覆盖中的 partial/unknown 清晰可见 → 定位固定源码 → 保存复核/摘录 →
关联调查案例 → 导出可核验审计包 → 重启后记录保留。
操作 API 与 UI 已接入；Docker Runtime 当前仍受环境阻塞，版本影响与确认结论尚不提供。

目前服务仅监听 loopback；没有多人身份/公网部署验收。整任务内存预算是地址空间上限，
不是测得峰值 RSS。SSE/热更新/PDF 不是首版必须，当前轮询/同源静态包/JSON-MD 可用。
