## 二、当前端到端数据合同（实际实现）

```text
实际静态诊断 ToolDiagnostic
  - severity: unassessed（仍保留）
  - candidate_cwe / consequence_cwe（若有）
     |
     +--> service.findings(report) [immutable source binding]
            |
            +--> smart_audit.severity_metadata() [unverified CWE heuristic]
            |      |--> /api/v1/overview/risks
            |      |--> /api/v1/scans/{id}/risks
            |      |--> /api/v1/scans/{id}/findings -> risk_presentation
            |      +--> /api/v1/scans/{id}/findings/{candidate} -> risk_presentation
            |
            +--> smart_audit._severity() [same heuristic scheduling, not confidence]
                    |--> candidate priority ordering
                    +--> authorized conditional deep source investigation
```

前端 `WorkspaceViews.tsx` 和 `JobDetail.tsx` 的颜色 Tag 不修改源报告/数据库。CWE 规则仅为**未验证的类型推测**，不代替 CVSS、触发可达性、动态产品影响。没有匹配 CWE 的候选仍显示未分级。静态 incomplete/blocked 不视为安全。

## 四、未验证或不属于本 PR 范围

- **浏览器端实机**：尚未在你的 localhost:8765 上点击真实页面；服务运行的是哪个 Commit、是否重构前端、浏览器缓存是否刷新须现场核对。
- **真实外部模型**：没有用付费 Provider 验证授权预览→R1→条件 R2；本 PR 不会推出多角色 Agent。
- **时间/跨版本自动 Agent**：尚未实现，见 issue #40；不能认为“智能审计”选项就等于自动模型调用。
- **漏洞证据裁决**：高可信必须满足既有独立 R0/static/source 证据门；N-day/1-day 不因有 CVE 名称直接确认。
- **关联已验证案例测试**：只做了字段映射；仍需构造具备真实 reachability passed 的 case/validation 端到端回归。
- **安全应用**：模型 Provider 外发需明确授权，默认禁自动外发；隐藏与可见只是 UX，后端才是权威范围和费用控制。
