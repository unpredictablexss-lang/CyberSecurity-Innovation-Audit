# 安装、复现与源码交付

工作台以 Python 3.10+ 的 Linux/WSL 环境为主要运行平台，需 Git、Python venv/pip、Node.js 22/npm。模型服务和隔离测试分别按需要配置。

## 首次安装

```bash
git clone https://github.com/unpredictablexss-lang/CyberSecurity-Innovation-Audit.git
cd CyberSecurity-Innovation-Audit
git switch main
cp config/workbench.example.json config/workbench.local.json
# 按部署机器编辑数据目录和受允许的源码根目录
bash scripts/setup_workbench.sh
bash scripts/start_workbench.sh --port 8765
```

浏览器打开 `http://localhost:8765`，API 文档为 `http://localhost:8765/docs`，健康检查为 `http://localhost:8765/api/v1/health`。启动器默认仅绑定本机回环地址。

`setup_workbench.sh` 创建 Python 环境、安装 `requirements-web.txt` 并执行前端锁定依赖安装和构建；`start_workbench.sh` 启动 API 及各类 Worker。默认虚拟环境为 `.venv-web`，可用 `OHSCANNER_VENV` 指定。

Windows 用户可在 WSL 中安装并从 Windows 浏览器访问。Windows 导入管道的专项支持不代表完整原生 Windows 工作台已完成验收。

## 本机配置

`config/workbench.example.json` 提供数据目录、源码根目录、性能模式及源码缓存配置。复制出的 `config/workbench.local.json` 被 Git 忽略，不随源码交付。

| 配置 | 用途 |
|---|---|
| `data_dir` | 任务、SQLite、报告及运行产物 |
| `target_roots` | 受允许的本地源码父目录 |
| `repository_cache` | 在线导入缓存目录、容量及剩余空间保护 |
| `OHSCANNER_CONFIG` | 指定外部配置文件 |
| `OHSCANNER_DATA`、`OHSCANNER_TARGET_ROOTS` | 覆盖数据目录与源码根目录 |

JSON 相对路径以配置文件所在目录解析；`~` 指服务账号主目录。源码根目录须在服务器端存在并满足权限和身份检查；在线缓存与手工登记目录的管理语义不同。

模型可在设置页配置，或由完整的 `OHSCANNER_LLM_*` 环境配置提供协议、地址、模型及密钥。环境配置生效时设置页只读；不要混用不完整环境变量与本地设置。密钥和 Provider 私有配置不能上传或打包。

智能审计策略在系统设置集中管理，新任务冻结策略；各调查流程的预算边界见[架构说明](架构与公共协议.md)。

## 更新已有部署

1. 记录当前提交，确认队列及正在执行的任务。
2. 正常停止已确认的本机服务，保留运行数据和本机配置。
3. 在干净或已妥善保留修改的源码目录更新，再安装/构建并启动：

```bash
git switch main
git pull --ff-only origin main
bash scripts/setup_workbench.sh
bash scripts/start_workbench.sh --port 8765
```

重启后核对健康检查、页面资源和正在运行的源码提交，并刷新浏览器。只更新 Git 不会替换已运行进程或旧前端资源。不要让多个实例同时使用同一个数据目录，也不要覆盖他人未提交的工作树。

## 验证与复现

仓库 CI 的主要顺序是前端测试/构建，再执行 Python 回归：

```bash
cd web
npm ci
npm test
npm run build
cd ..
.venv-web/bin/python -m unittest discover -s tests -v
git diff --check
```

完整工作台测试需要 `requirements-web.txt` 和构建后的 `web/dist`。记录提交、环境、通过/失败/跳过及原因，不沿用其他分支的测试数量。

真实目标实验使用独立数据目录，记录仓库完整 SHA、路径、检测器版本、模型/提示词版本、精确命令、原始输出及摘要。隔离验证还要记录目标、镜像、依赖、触发条件和对照；扫描子进程的资源限制不替代动态测试隔离。

性能复测定义见[benchmarks](../benchmarks/)。历史性能、已披露 CVE 样例及合成测试按各自边界使用，不能自动作为当前版本效果结论。

## 源码与演示材料交付

从选定且已验证的提交导出源码：

```bash
git rev-parse HEAD
git archive --format=tar.gz --output=../ohscanner-source.tar.gz HEAD
```

源码应包含程序、锁定依赖、配置示例、安装脚本和当前文档。安装时重建环境与前端；不直接复制虚拟环境或 `node_modules`。

演示数据、固定目标清单、报告及复现材料单独组织，核对许可和分发范围。排除本机数据库、缓存、Provider 密钥、运行配置及未授权第三方源码。前端内嵌 MiSans 资源应连同[授权说明](../web/src/assets/misans/NOTICE.md)保留，不单独分发字体。

## 文档维护

`docs/` 仅保留阅读入口、项目现状、架构、操作手册、Agent/实验说明及本指南六份文档。功能和限制按当前源码维护，不追加逐日 PR、临时端口、个人路径和分支流水。

原始来源清单和实验记录保留于 `research/` 或 `benchmarks/`；被移除的阶段设计可从固定 Git 提交追溯。修改文档时检查入口与本地链接，避免形成多套相互冲突的当前状态说明。
