# 开发、协作、复现与最终打包

更新：2026-10-19。当前本机使用 Ubuntu 22.04 WSL2，Python3.10、Node22。项目可从任意 Linux/WSL 克隆目录部署；运行路径通过本机配置提供，不写入源码。
一个 GitHub 项目；app 是负责人的日常源码工作树，验收通过的 worktrees 分支也可独立提供服务，外围目录是管理入口，不整体当交付源码包。

## 新环境安装

自动部署入口：Windows 双击根目录 `deploy-windows.cmd`；Linux 执行 `bash deploy-linux.sh`。Windows 的 PowerShell 入口可指定 `-Distribution Ubuntu -Port 8765`，Linux 可指定 `--port 8765`。两者共用 Linux 安装流程及现有 API/Worker，不依赖 Docker Desktop。自动安装支持 Ubuntu 22.04+/Debian 12+、x86_64/arm64；当前实测平台及边界以状态文档和部署验收记录为准。

脚本安装缺失的 Python 3.10+/venv、Git、curl、CA 证书、xz、flock；普通用户通过 sudo 安装系统包。Node 22.16.0 下载到 `.deploy/`，校验内置官方 SHA-256，不替换系统 Node。Python 依赖安装到独立虚拟环境，执行 `npm ci` 和 TypeScript/生产构建后以前台方式启动正式服务。重复执行保留数据库和配置，重新检查依赖及构建；停止后可再次运行。安装失败返回非零并保留日志，不显示通过。不要同时用同一源码目录启动多套服务；另取源码副本或设置不同 `OHSCANNER_DEPLOY_HOME`、数据、端口。

无已有本机配置时，Linux 数据默认 `.deploy/data`，目标根目录 `.deploy/targets`；Windows 入口默认将整个部署目录放在 WSL `~/.local/share/ohscanner/windows-源码目录摘要/`，避免 Windows 文件系统中的数据库锁和虚拟环境问题，启动时打印路径。`OHSCANNER_DEPLOY_HOME` 可更换整个部署目录，`OHSCANNER_CONFIG`、`OHSCANNER_DATA`、`OHSCANNER_TARGET_ROOTS`、`OHSCANNER_VENV` 仍可覆盖。已有 `config/workbench.local.json` 不覆盖。自测使用独立配置、临时 Git 样例和数据库，日志/报告保存在部署目录的 `smoke-*/`；不调用模型或执行目标代码。首次联网需要访问系统软件源、nodejs.org、PyPI 和 npm registry，可使用各工具的代理环境变量。

仅安装：Linux `bash deploy-linux.sh --setup-only`，Windows `deploy-windows.ps1 -SetupOnly`。端到端自测：Linux `bash deploy-linux.sh --port 18867 --smoke-test`，Windows `deploy-windows.ps1 -Port 18868 -SmokeTest`。健康检查通过后访问 `http://localhost:端口`；模型 Provider、目标源码及可选动态验证 Docker 环境按需另配，空配置可以启动和静态扫描。

Windows 需要支持 WSL2 的系统和已开启的硬件虚拟化。脚本在缺少指定发行版时执行 `wsl --install --distribution Ubuntu --no-launch`；安装功能可能要求管理员权限、重启及首次发行版初始化，遇到时按系统提示完成后重跑。不能承诺未启用虚拟化的全新 Windows 在一次点击且无需重启时完成安装。现有 WSL 使用非默认名称时，通过 `-Distribution 名称` 选择。

```bash
git clone git@github.com:unpredictablexss-lang/CyberSecurity-Innovation-Audit.git
cd CyberSecurity-Innovation-Audit
git switch main
git pull --ff-only origin main
cp config/workbench.example.json config/workbench.local.json
# 编辑本机数据目录和已批准源码根目录
bash scripts/setup_workbench.sh
bash scripts/start_workbench.sh --port 8765
```

先安装 Python 3.10+ venv/pip、Git、Node 22/npm；setup 锁定前端依赖并构建。
默认 `.venv-web`；`OHSCANNER_VENV` 可覆盖。`config/workbench.example.json` 是可迁移模板；本机副本 `config/workbench.local.json` 被 Git 忽略。相对路径按该配置文件目录解析，`~` 展开为当前用户主目录。也可设置 `OHSCANNER_CONFIG` 指向外部 JSON 配置；环境变量 `OHSCANNER_DATA` 与 `OHSCANNER_TARGET_ROOTS` 优先级更高，源码根目录列表使用当前 OS 的路径分隔符。

完整扫描和受限 Worker 当前支持 Linux/WSL，Windows 原生执行与 macOS 尚未验收；新环境须重建虚拟环境、安装依赖并执行本指南中的回归测试。Windows 用户从浏览器访问 WSL 服务 `http://localhost:8765`，同源 API 文档位于 `/docs`。Docker 动态验证还要求可用的 Docker daemon 和已固定镜像。

2026-10-22 发布核对：8765 的未提交源码增量须在最新 main 上逐项合并，不能把较旧运行目录整体覆盖主线。当前统一界面包含彩色 CWE/CVE 标签、AI 初判调查优先级与相似候选归组、批量深入追查、具体失败诊断及默认折叠的限制详情；时间增量扫描和指定提交比较分别显示。源码、依赖锁文件和构建脚本随 main 提供；web/dist、node_modules、虚拟环境、仓库缓存、任务数据库、报告和 Provider 密钥不上传。队友须执行 setup 重新构建，并从刚更新的目录启动服务，避免旧服务继续提供旧资源。

同一 main 版本提供相同页面与功能代码；任务、候选、报告、仓库登记与源码缓存随各自数据目录保存。Provider 接口/地址/模型/密钥、源码目录和智能审计预算也须在该机器配置，不会随 git pull 继承负责人设置。静态审计无需模型；AI 调查需配置 Provider 并确认发送范围。不要用另一个机器的整个 data 目录来代替配置。

## 打包交付

精简可部署源码包（包含本地 curated knowledge，不含开发测试及其余历史研究资料）：`python scripts/package_deployment.py --ref HEAD --output /tmp/ohscanner-source.zip`。导出只读取已提交的 Git 对象；源码、部署脚本变更须先提交。ZIP 内 `DEPLOYMENT_SOURCE.json` 记录完整源码 commit。解压后运行上述 Windows/Linux 入口，首次联网安装依赖和构建；包不是离线二进制安装器。

从最终验收 Git commit 导出源码，不直接压缩 ~/ohscanner：
```bash
git archive --format=tar.gz --output=/tmp/ohscanner-source.tar.gz HEAD
```
HEAD 必须已验收、已提交；archive 不含未提交文件、Git历史或忽略的前端构建。
源码包包含代码/锁定依赖/配置示例/安装脚本/六份文档，安装时重建前端与环境。
演示数据/固定源码对象清单/报告另包，逐项核对许可与分发范围；
不混入 .git、venv、node_modules、Key、本机数据库或全部研究缓存。
当前支持本机安装，不承诺“完整原生Ubuntu/离线交付已验收”。

## 2026-10-21 Issue #39 在线源码缓存部署配置

新版本可选配置 `repository_cache.roots`、`max_bytes`、`minimum_free_bytes`，示例见 `config/workbench.example.json`；对应环境变量为 `OHSCANNER_REPOSITORY_CACHE_ROOTS`、`OHSCANNER_REPOSITORY_CACHE_MAX_BYTES`、`OHSCANNER_REPOSITORY_CACHE_MIN_FREE_BYTES`。相对路径相对于配置 JSON 所在目录解析。默认缓存位于 `data_dir/repo-cache`，限额 `0` 表示不配置总量上限，默认保留至少 1 GiB 空闲空间。缓存目录不是设置页可发现源码根，不接受符号链接；自定义缓存盘应预先挂载并由服务账号具有目录读写权限。缓存对象目录含 Git 元数据，不应由外部任务原地改写。旧 `/operations/source-sync` 路径语义保留；新在线选择流程由 `repository_import_scan` 操作执行。
