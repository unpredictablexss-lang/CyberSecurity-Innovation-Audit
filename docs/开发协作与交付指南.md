# 开发、协作、复现与最终打包

更新：2026-10-16。当前主环境为 Ubuntu 22.04 WSL2、Python 3.10、Node 22；Windows 浏览器访问同源服务。

## 何时读取

安装、启动、测试、团队职责、验收提交、性能复现或最终打包时读取。检测器语义和证据门仍以《架构与公共协议》为准。

## 新环境与统一入口

```bash
git clone git@github.com:unpredictablexss-lang/CyberSecurity-Innovation-Audit.git
cd CyberSecurity-Innovation-Audit
git switch main
git pull --ff-only origin main
bash scripts/setup_workbench.sh
bash scripts/start_workbench.sh --port 8765
```

本机统一入口：

```bash
cd ~/ohscanner/app
../bin/oh doctor
../bin/oh check
../bin/oh build
../bin/oh start
```

配置使用 `config/local.json`，不在 Git 中保存 Key。`OHSCANNER_DATA` 保存 DB/artifacts，`OHSCANNER_TARGET_ROOTS` 限定可登记仓库。扫描不隐式 fetch；重启后 running 记 interrupted，不伪造续跑。

## 每轮验证

```bash
python -m pip install -r requirements-web.txt
python -m unittest discover -s tests -q
python scripts/check_docs_context_budget.py
git diff --check
cd web
npm ci
npm run build
```

Windows 的 `python` 可能只是占位程序；实际验证使用配置的 WSL `.venv-web/bin/python`。真实组件对照必须使用新 `--data-dir`，避免与运行中的 Worker 争锁。缺失 optional deps 必须记录 exact error/skip，不能写成通过。

浏览器验收使用确定性 loopback HTTPS Git 夹具；公网同步另需真实网络复测。完整组件身份、五组件对照和历史基线命令以 `scripts/README.md` 及当前脚本参数为准。

## 团队职责与交付

负责人维护公共 contracts/runner/catalog、Git/版本、API/Worker/storage、CI、统一验证和报告；A 维护 C/C++ Detector、对照、方法卡和家族 Harness；B 维护 IPC/接口 Detector、授权边界和 Harness。

最小交付必须填写 branch + full head/base SHA、迁入提交/文件、公共接口变化、exact argv/env、通过/失败/skip、target repo/commit/tree/scope/profile/Detector、候选与覆盖、四类控制、holdout、验证/unknown 和依赖冲突。负责人用独立 worktree 选择性迁入，不覆盖整仓、不强制 reset。

## 打包交付

从已验收 commit 导出：

```bash
git archive --format=tar.gz --output=/tmp/ohscanner-source.tar.gz HEAD
```

源码包包含代码、锁定依赖、配置示例、安装脚本和六份当前文档；不包含 `.git`、venv、node_modules、Key、数据库、大二进制或完整研究缓存。演示数据、固定源码对象和报告另包并逐项核对许可证。当前承诺本机安装，不声称完整原生 Ubuntu/离线交付已验收。

## 文档维护

`docs/` 只保留 README、现状、架构、开发、面板、Agent 六份 Markdown。历史证据放 Git 或 `research`；新增功能同步更新状态和对应专项文档。`PROGRAM_STATUS.md` 只指向状态表。提交前保持 dirty worktree 和证据，push 前说明验证与限制，未获授权不 Draft Ready/merge。
