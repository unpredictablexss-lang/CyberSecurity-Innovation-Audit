## OpenHarmony 多仓源码获取

赛题中的 `https://www.openharmony.cn/download` 当前返回 404，不能作为可复现的源码来源。需要完整 OpenHarmony 工作区时，使用 GitCode manifest 在独立源码目录初始化；不要把下载到的源码仓库提交进 OHScanner Git。

```bash
# 安装 repo 工具（如果尚未安装）
mkdir ~/bin
curl https://raw.gitcode.com/gitcode-dev/repo/raw/main/repo-py3 -o ~/bin/repo
chmod a+x ~/bin/repo
export PATH=~/bin:$PATH

# 初始化并同步代码（HTTPS 方式）
repo init -u https://gitcode.com/openharmony/manifest.git -b master --no-repo-verify
repo sync -c
repo forall -c 'git lfs pull'
```

该命令组用于取得完整多仓源码，不是 OHScanner 扫描流程的一部分；OHScanner 仍不隐式 fetch。同步完成后必须记录 `repo --version`、manifest URL/revision、同步日期、LFS 状态，以及每个目标仓库的 remote、full commit SHA、tree SHA 和本地 source hash，再把固定目标登记到 `OHSCANNER_TARGET_ROOTS`。`master` 是移动分支，复现实验必须固定 commit/tree，不能只记录 `repo sync -c` 成功。`--no-repo-verify` 只能在受控镜像环境中使用，并应另行保存 `repo-py3` 的下载来源和 SHA-256。

此前实验使用的仓库不是由上述命令现场生成，具体来源和固定对象见《Agent 方案与可复核对照实验》的“实验源码来源与复现边界”。

## 每轮验证

```bash
python -m pip install -r requirements-web.txt
python -m unittest discover -s tests -q
python scripts/check_docs_context_budget.py
git diff --check
cd web
npm ci
npm run build
```

Windows 的 `python` 可能只是占位程序；实际验证使用配置的 WSL `.venv-web/bin/python`。真实组件对照必须使用新 `--data-dir`，避免与运行中的 Worker 争锁。缺失 optional deps 必须记录 exact error/skip，不能写成通过。

浏览器验收使用确定性 loopback HTTPS Git 夹具；公网同步另需真实网络复测。完整组件身份、五组件对照和历史基线命令以 `scripts/README.md` 及当前脚本参数为准。

## 团队职责与交付

负责人维护公共 contracts/runner/catalog、Git/版本、API/Worker/storage、CI、统一验证和报告；A 维护 C/C++ Detector、对照、方法卡和家族 Harness；B 维护 IPC/接口 Detector、授权边界和 Harness。

最小交付必须填写 branch + full head/base SHA、迁入提交/文件、公共接口变化、exact argv/env、通过/失败/skip、target repo/commit/tree/scope/profile/Detector、候选与覆盖、四类控制、holdout、验证/unknown 和依赖冲突。负责人用独立 worktree 选择性迁入，不覆盖整仓、不强制 reset。

## 打包交付

从已验收 commit 导出：

```bash
git archive --format=tar.gz --output=/tmp/ohscanner-source.tar.gz HEAD
```

源码包包含代码、锁定依赖、配置示例、安装脚本和六份当前文档；不包含 `.git`、venv、node_modules、Key、数据库、大二进制或完整研究缓存。演示数据、固定源码对象和报告另包并逐项核对许可证。当前承诺本机安装，不声称完整原生 Ubuntu/离线交付已验收。
