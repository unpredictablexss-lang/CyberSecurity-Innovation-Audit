# 项目现状与交付范围

文档整理：2026-10-27。源码核对基线：`3fc4b1d6bc7664538edbd3ab1aa88ace0a5e4aad`。本页汇总仓库当前实现和验证边界，不代表某台机器正在运行的版本。

## 项目定位

OHScanner 面向 OpenHarmony 源码审计，将固定版本扫描、自研检测器、模型辅助调查、人工复核、隔离测试和报告组织到同一工作台。CLI 与 Web 共用扫描内核。

主要流程为：登记或导入仓库 → 固定提交与路径 → 静态检测 → 候选整理与 AI 调查 → 人工复核 / 适用的隔离测试 → 导出报告。

## 当前实现

| 能力 | 代码入口 | 交付边界 |
|---|---|---|
| 源码登记与在线导入 | `src/workbench/repository_import.py`、`source_roots.py`、`source_catalog.py` | 本地 Git 仓库登记、受控根目录及在线固定版本导入；在线导入成功后可排入静态扫描 |
| 固定版本与源码索引 | `src/ohscanner/git_source.py`、`indexing.py` | 固定 commit/tree/blob、路径与源码摘要，记录解析和分析覆盖 |
| 自研静态检测 | `src/ohscanner/detectors/` | C/C++、IPC/接口、Ark Runtime、敏感信息和已披露组件 CVE 等研究检测器；适用范围和版本条件由检测器决定 |
| 仓库审计 | `src/workbench/api.py`、`planning/` | 预览扫描范围、固定版本、创建任务，保存候选、覆盖和原始报告 |
| 时间增量与跨版本审计 | `src/workbench/operations.py`、`operations_api.py` | 按日期选择提交范围，或比较指定提交、分支、标签与版本矩阵；比较候选变化 |
| 渐进式智能调查 | `src/workbench/progressive_triage/`、`agent.py` | 候选分组、AI 初步分析、只读工具深入追查、来源与引用校验、策略和执行记录 |
| 风险与人工复核 | `src/workbench/service.py`、`store.py` | 分别展示风险、源码可信程度、人工意见与复现情况，保留历史记录 |
| 报告与隔离测试 | `src/workbench/operations_api.py`、`validation*.py` | 扫描及案例报告导出、草稿生成和已登记测试的受控执行；逐项核对目标和适用条件 |

## 设计中值得关注的部分

1. **同一内核服务多个入口。** 仓库、时间和跨版本审计复用固定源码、检测器及结果协议。
2. **以源码证据驱动调查。** 候选、引用、工具返回和报告绑定固定版本及摘要，模型解释不能直接改写原始扫描结果。
3. **逐层投入调查资源。** 静态发现和候选整理后，再对选定候选开展 AI 初步分析与深入追查，记录覆盖、预算及未解决问题。
4. **区分源码判断和运行验证。** 高可信源码链、已披露 CVE 对应关系、组件 Harness 和产品漏洞确认分别展示。

这些是实现特点，不等同于已证明优于其他工具；比较收益须通过独立实验支持。

## 验证与已知限制

- 仓库提供 Python 回归、前端测试和构建 CI。测试结论须绑定对应提交；历史通过数量不能作为当前版本的新测试结果。
- 完整工作台以 Linux/WSL 为主要运行环境。Windows 在线导入管道已有专项修复和回归，这不等于全流程 Windows 原生部署已验收。
- AST 与语法调用关系不等于完整类型、宏展开、控制流或跨过程语义证明。未分析范围继续显示局限。
- 模型接口支持 Responses 和 OpenAI 兼容 Chat Completions；具体服务商、模型、工具调用及结构化输出仍须实际核对。
- 源码调查、历史补丁对照、已披露 CVE 匹配和组件测试不能直接证明当前产品可利用性。真实入口、权限、触发条件、影响及修复重验需要独立证据。
- 性能记录见[组件性能规模实测](../benchmarks/组件性能规模实测.md)，用于说明对应历史提交的组件级平台成本；不是当前 main 的准确率或全 OpenHarmony 整树能力证明。

## 评阅与演示建议

先按[操作手册](面板操作手册.md)选择一个已准备好的固定版本仓库，完成静态扫描，打开覆盖、候选和报告。再演示时间范围或两个版本的比较；如已配置可用模型，则展示一次明确授权的候选调查，核对引用及未知项。

评阅材料可依次提供源码提交号、环境与启动方式、固定目标清单、任务及报告、适用的复现与修复记录、实验结果和限制。原始材料保存在[研究目录](../research/)和[基准目录](../benchmarks/)，不能只以截图或候选数量替代证据。

## 后续验证重点

- 在新的 Linux/WSL 环境从固定提交重建，完成扫描、调查、报告及适用隔离测试的端到端复核。
- 对有价值的候选补齐产品入口、权限、影响和修复重验；不为演示修改确认等级。
- 冻结独立真值集，比较静态基线、单轮模型与工具型 Agent，并测量时间、资源及人工成本。
- 扩大组件与版本范围时同时报告分析覆盖和未分析原因。
