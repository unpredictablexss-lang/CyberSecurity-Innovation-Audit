# OHScanner 面板操作手册

> 2026-10-20 长期授权生效：按任务自主开发、测试、隔离组件验证和交付，无需再次申请目录/组长许可；产品资料、真人盲评和正式准入不阻塞开发。详见根 AGENTS.md。历史结果不构成当前审批规则。

这份手册按“我要做什么”来写。第一次使用时，先做一次普通扫描；确认结果能打开后，再试时间区间或版本比较。

## 先记住三件事

1. 面板只扫描你登记的本地 Git 仓库。先在“仓库与版本”登记仓库，再去创建任务。
2. 扫描会固定到一个具体版本。后续分支更新不会改变已经提交的任务。
3. 扫描结果里的“候选”是需要人检查的线索，不等于已经确认的漏洞。任务完成也不等于发现了漏洞。

## 我只想先扫一次代码

1. 打开“仓库与版本”，在“登记本地仓库”填写：
   - **仓库标识**：自己容易认出的名字，例如 `openharmony/commonlibrary_c_utils`。
   - **WSL 仓库绝对路径**：仓库所在的完整路径，例如 `/home/audit/openharmony-targets/commonlibrary_c_utils`。
2. 点击“登记仓库”。如果报错，先检查路径是否存在、是否为 Git 仓库，以及它是否在允许的目录里。
3. 打开“新建审计”：
   - 选仓库。
   - 选一个分支、标签或提交版本。第一次可以用默认分支。
   - **纳入路径**填 `.` 表示整个仓库；只想扫一部分时填目录，例如 `interfaces`。
   - 勾选要用的检测器。
4. 点击“冻结版本并创建任务”，然后在任务列表里点进去看进度和结果。

## 我想看一段时间内的改动

打开“源码运营与证据闭环”里的“提交者日期区间”：

1. 选仓库和分支。
2. 选择开始时间、结束时间和时区。默认时区是中国时间 `Asia/Shanghai`。
3. 先点“预览”，看看命中了多少提交，以及实际会扫描哪个起点和终点。
4. 确认范围后，选择检测器和纳入路径，再提交任务。

时间范围包含开始时刻，不包含结束时刻。举例：选 10 月 1 日到 10 月 8 日，表示包含 10 月 1 日零点，截止到 10 月 8 日零点之前。系统按提交者填写的提交时间筛选，并沿主线提交顺序确定扫描范围；范围里可能夹着日期之外的中间提交，预览会提示这一点。

## 我想比较两个版本

如果手头有两个完整提交号，在“两个 SHA 区间”里分别填起点和终点，再选择仓库、检测器和路径。通常用于比较同一条历史线上“改动前”和“改动后”。

如果面板显示“跨分支比较”页签，选同一仓库的两个分支或标签即可，不需要先建调查案例。系统会在提交时把两个分支各自固定到当时的提交版本，再比较这两个端点；之后分支继续更新也不会改动这次结果。

跨分支比较只看两个端点的差异，不会把中间每个提交都扫一遍。两个版本之间候选的出现或消失，只说明扫描结果有变化；是否为真实漏洞、由哪个版本引入或修复、影响哪些产品版本，都还需要单独核实。

## 其他页签什么时候用

- **同步源码**：只有仓库尚未下载或需要更新时才用。它负责下载代码，不会自动扫描；完成后仍要去“仓库与版本”登记并创建扫描。
- **版本矩阵**：已经有一个调查案例，想把同一检测器跑在多个固定版本上时使用。它不是普通扫描的第一步。
- **只读调查**：从已有扫描候选里补充源码位置、调用关系等信息；不会自动确认漏洞，也不会调用模型。
- **隔离验证**：只用于项目已登记的测试 Harness。先看清楚目标版本和依赖版本，确认这是受控测试任务后再提交。

## 怎么看任务结果

- **排队中**：还在等待 Worker。
- **运行中**：正在扫描。可以点开任务看日志。
- **已完成**：任务正常结束，接着检查覆盖范围和候选。
- **有局限地完成**：任务有结果，但部分内容没有成功检查；不能把没检查的部分当成安全。
- **受阻 / 失败**：没有得到完整结果。先展开任务详情看原因，修正仓库、版本或运行环境后再重试。
- **已取消**：任务被停止，不代表扫描范围安全。

看到候选后，打开它核对固定版本、文件位置、源码和证据说明。若覆盖不完整、路径不在纳入范围或工具报错，把结论记为“未知”，不要写成“没有漏洞”。

## 常见问题

**仓库列表里找不到仓库？** 先去“仓库与版本”登记。仓库目录需要在服务允许访问的路径内。

**分支名填了却报错？** 回到“仓库与版本”点击“查看版本”，复制列表里的分支或标签名称。日期区间需要能识别的分支；两个 SHA 功能需要完整提交号。

**为什么任务完成了，结论还是未知？** “完成”表示任务流程结束，不代表漏洞已确认。真实漏洞结论需要核对源码、入口、影响和复现证据。

**看不到“跨分支比较”或时间预览怎么办？** 这两个入口在较新的面板版本中提供。当前 GitHub `main` 上的界面可能还没有这些入口；更新应用代码并重启服务后才会出现。单独更新这份手册不会替代码升级。
