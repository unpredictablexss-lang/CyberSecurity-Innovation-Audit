# OHScanner 面板操作手册

先完成一次固定版本静态扫描，再演示时间或版本比较。运行环境准备见[安装与交付指南](开发协作与交付指南.md)。

## 准备源码

打开“系统设置 → 源码与仓库”（`#/settings/sources`），选择一种方式：

- **已有本地仓库**：确认服务端的源码根目录受允许访问，再发现或登记 Git 仓库。填写仓库名称及服务器上的绝对路径；WSL 服务填写 Linux 路径。
- **在线导入**：在“OpenHarmony 在线仓库目录”选择仓库，先查看默认分支对应的完整提交，再确认“下载并开始扫描”。下载成功后会自动排入静态扫描，在任务中心查看导入和扫描进度。

在线目录提供仓库元数据，不独立证明官方身份。普通源码同步表单可另外选择是否同步后扫描，请检查表单选项。

## 做一次仓库扫描

1. 打开“仓库审计”（`#/audits/repository`）。
2. 选择已登记仓库和分支、标签或完整提交。
3. 选择纳入路径；`.` 表示所选仓库范围，子目录可用于缩小演示范围。
4. 查看检测能力和范围预览。默认自动尝试已登记研究检测器，各检测器按语言及固定版本条件判断是否适用。
5. 第一次选择静态扫描并创建任务，不必配置模型。
6. 在“任务中心”打开任务，查看事件、覆盖、候选及报告。

成功标志是任务留下真实报告，且能够核对完整提交、路径、检测器与覆盖。结果为零候选也可能是有效运行，但需要同时检查是否存在未分析或失败范围。

## 做时间增量扫描

打开“时间增量扫描”（`#/audits/time`），选择仓库、分支、开始时间、结束时间和时区，再预览提交范围。

时间选择包含开始时刻、不包含结束时刻；系统使用 committer 时间和 first-parent 历史确定固定范围。以预览显示的完整起止提交、命中提交和局限为准，再创建任务。

查看结果时分别核对起点/终点扫描与候选变化。该功能不代表逐个扫描区间内每次提交，也不能直接确定漏洞引入或修复时间。

## 比较两个版本

打开“跨版本安全审计”（`#/audits/versions`），按表单选择：

- **指定提交比较**：填写基准与目标完整 SHA。
- **分支 / Tag 比较**：选择两个引用，创建时固定它们当时对应的完整提交。
- **版本矩阵**：先有绑定仓库候选的调查案例，再选择多个固定版本。

时间选择与指定版本比较是两个独立入口。比较结果中的新增、持续或消失是候选观察关系，需结合源码和测试判断漏洞影响。

## 对候选进行 AI 调查

1. 在“系统设置 → 模型服务”配置协议、地址、模型和密钥，并检查连接。兼容服务需支持所用结构化输出及工具调用。
2. 在“智能审计策略”查看调查范围和资源策略。已有任务继续使用创建时冻结的策略。
3. 从任务候选或风险中心进入 AI 初步分析/深入追查。
4. 阅读发送内容预览，核对仓库、完整提交、候选、源码范围、参考材料、目的地和额度，再明确授权。
5. 在操作详情查看模型步骤、源码引文、反证、未解决问题和失败原因。

未经授权不会自动外发源码。已配置或连接测试成功只说明接入条件，不说明模型分析有效。高可信源码链和“建议继续调查”也不等于漏洞已确认。

## 查看风险、复核和报告

在“风险中心”打开候选，分别阅读初步风险、源码可信程度、人工复核和实际复现情况。必要时建立调查案例，补充入口、权限、触发条件及修复对照。

扫描报告保留原始结果；案例报告汇总绑定的源码、调查与复核记录。导出 JSON/Markdown 后，核对任务、提交、候选和报告摘要是否一致。

已有 PoC/修复草稿应作为待核验材料；隔离验证只运行已登记且适用的测试。测试成功说明什么，必须按测试目标与产品入口分别说明。

## 状态和常见问题

| 页面状态或现象 | 如何处理 |
|---|---|
| 排队 / 运行中 | 查看 Worker、事件与实际阶段 |
| 已完成 | 继续检查覆盖和候选，不据此确认漏洞 |
| 有局限地完成 | 保留有效结果，阅读未分析范围与原因 |
| 失败 / 受阻 / 中断 | 查看具体错误，修正环境或范围后显式重试；旧记录保留 |
| 取消 | 已有结果仍可查看，未完成范围保持未知 |
| 仓库不可用 | 检查服务端路径、受控根目录、Git 对象及访问权限 |
| 菜单或功能与本文不同 | 核对正在运行的源码提交；拉取代码后需重建前端、重启服务并刷新浏览器 |

任务详情中的“停止智能研判”和“取消整个审计”作用范围不同，先阅读按钮提示。不要通过删除数据库或强杀无关进程来清空队列。

## 建议演示顺序

登记/导入一个准备好的仓库 → 固定版本静态扫描 → 查看覆盖和候选 → 时间或版本比较 → 一次授权的 AI 调查（可选）→ 人工复核与报告导出。

演示前检查模型、网络及隔离测试环境；发生失败时展示真实错误和已保留的结果。
