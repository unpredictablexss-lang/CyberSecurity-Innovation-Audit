# OHScanner 工具使用说明书

本指南按一次安全审计的实际流程组织：接入源码、创建任务、跟踪结果、复核候选并导出报告。

## 接入源码

在“仓库与版本”登记已有本地 Git 仓库，填写仓库标识和服务可访问的绝对路径。在线仓库可从“同步源码”检索公开项目、预览分支和提交并同步到本地工作区；同步完成后登记仓库，即可创建审计任务。

## 创建审计任务

打开“新建审计”，选择仓库、分支/Tag/Commit、纳入路径和检测器。选择固定提交后创建仓库快照审计，任务会记录完整 Commit、Git Tree 和扫描路径。

- **仓库快照**：对单一固定版本进行扫描。
- **时间增量**：在“提交者日期区间”选择起止时间和时区，先预览命中提交及扫描端点，再提交任务。时间范围包含起点、不包含终点。
- **跨版本比较**：选择同一仓库的基准版本和目标版本，比较两个固定端点的候选变化。

## 在任务中心查看进度

任务详情列出固定版本、扫描范围、检测器计划、阶段状态、覆盖情况、日志和报告入口。状态含义如下：

- **排队中 / 运行中**：任务等待或正在执行。
- **已完成**：任务报告已生成。
- **有局限地完成**：报告列出已完成范围和未完成阶段。
- **受阻 / 失败**：打开阶段记录查看原因，修正环境或范围后再重试。
- **已取消**：流程已停止，任务记录仍可查看。

## 在风险中心复核候选

风险中心可按仓库、Commit、检测器、风险等级、漏洞状态和人工复核状态筛选。打开候选详情，核对源码路径、行号、固定版本和检测证据；在“候选证据与人工复核”中填写引用行范围、判断依据、复核状态和待补材料，保存后记录会追加到审计轨迹。

示例任务中，libpng 的 `arm/palette_neon_intrinsics.c:63` 和 `:108` 分别对应 RGBA、RGB Neon 路径，人工复核记录为“合理怀疑·待补证”。两处代码位置关联同一 CVE-2026-33636。

## 选择研判流程

1. **静态扫描 + 人工审计**：本地检测器生成候选与源码证据，研究人员直接复核。
2. **本地排序 + 批量 AI 审计**：先在本地归并、排序候选；用户选择批次并核对授权范围后，可发起初步筛查或进一步深查。
3. **一键智能审计**：创建任务时完成授权，静态扫描后自动运行初步研判，并按策略对指定候选进行只读工具追查。

## 查看知识库引用

在候选调查页选择“模型辅助调查”，点击“预览本次将发送的数据”。预览卡片展示本地 BM25 检索状态、索引文件数、语料 SHA-256，以及参考资料的路径、行范围、片段和资料 SHA-256。调查完成后，在操作结果详情中查看随结果保存的引用记录。知识库材料用于相似案例参考，并与当前固定版本的源码引证分列展示。

## 管理案例、运行 PoC 与导出报告

在案例管理中将相关候选和复核记录关联到案例。PoC 页面选择适用的固定复现测试，查看源码版本和隔离环境后启动，并在结果页查看运行状态与日志。

报告中心提供 JSON、Markdown、manifest 和复核包导出。已关联智能调查结果的案例报告会在“知识库参考资料”小节列出检索元数据与引用片段；扫描源码引证和知识库资料分别展示。导出时保存任务 Commit 和报告 SHA-256，便于归档及后续复验。

## 停止任务与常见问题

任务详情中的“停止智能研判”用于停止该任务的模型操作；“取消整个审计”用于停止扫描及后续调度。操作完成后可继续查看已有任务记录。

- **仓库未显示**：先在“仓库与版本”登记并检查路径权限。
- **分支或提交无法解析**：使用版本列表中的名称，完整提交号可从 Git 版本记录复制。
- **覆盖范围不完整**：在报告中查看文件解析状态和阶段记录，再调整纳入路径或扫描配置。
