# 架构、模块边界与公共协议

更新：2026-10-16。实现状态以当前 checkout、固定实验和《项目现状与下一步》为准。

## 何时读取

修改 Detector 语义、contracts、Runner、Catalog、Git/版本服务、schema、覆盖或证据门时读取本文件。纯 UI、命令或实验任务不需要加载全文。

## 一套内核，多个入口

本地 Git 对象 → 固定 commit/tree/scope → 语言索引/AST 覆盖 → Catalog Registry Runner → 候选、覆盖、EvidenceObligations。CLI 和 React 面板经同一执行层；API/Worker 只是持久化和调度入口。源码同步、区间、版本矩阵、调查和验证复用同一任务/证据服务，不另造扫描器。

生产 Detector 不依赖外部扫描器或历史 verdict。`src/providers` 只规范化离线工具结果，历史 bake-off 留在 `research/benchmark`。扫描只读本地 pinned Git objects；fetch/checkout 是独立显式操作。

## 当前实际契约

主要类型在 `src/ohscanner/contracts.py`：

- `ScanRequest`：repository、full commit、snapshot、profile、provenance。
- `SourceUnit`：相对路径、language、text、SHA-256、parse status。
- `ScanContext`：排序去重的 SourceUnits 和 shared facts。
- `DetectorFinding`：位置、rule/message、候选 CWE、EvidenceObligations；consequence 仍是候选。
- `DetectorRun`：ID/version/status、analyzed files、findings、limitations、可选 file outcomes。
- `Detector`：ID/version、languages、required facts、`detect(context, units)`。

Registry 显式批准 factory，浏览器不能传 Python 模块名或 Shell 命令。公共契约/协议变更必须独立提交并带兼容性测试，不能混入 Detector 修复。

## v1/v2 与身份

第一方结果使用 source-bound schema v2，逐诊断绑定 source SHA；历史外部结果继续只读兼容 v1。不得重写历史 JSON、report hash、candidate/diagnostic ID、review 或 EvidenceObligation。

来源至少绑定 repository/full commit/tree/snapshot/file/blob/source SHA、Detector ID/version/rule/scope/profile。缺项记录为 unknown。候选身份和 finding projection 可以追加稳定映射，但不得伪造旧 ID 字节或来源。

## 状态、覆盖与证据门

Web task、Detector execution、file coverage、review 和 vulnerability level 必须分开：

- task：queued/running/completed_with_limitations/failed/cancelled/timed_out/interrupted。
- Detector：completed/blocked/failed。
- 文件：complete/partial/not_analyzed/failed，parse 状态另记。
- 安全结论：默认 candidate/unassessed；unknown/partial/failed/unexecuted 不是 safe 或 miss。

确认/报告必须绑定固定目标和来源，证明真实入口/权限边界、可达敏感操作、触发条件、具体 CIA 影响及可审计证据。AST/pattern 不证明 ownership、dominance、并发、attacker control 或 impact。

普通扫描资源限制不是逐 Detector 沙箱。动态 Harness 只允许独立 Docker Worker、无网络、去 capabilities、只读根目录和资源限制；组件触发不证明产品入口可达。

## 扩展原则

AST 缓存可绑定 blob+parser+配置；跨文件语义必须绑定依赖、宏和编译配置。2000 文件、32MiB 总源码、1MiB blob 是当前限制。扩容先做 batch、分片/聚合和覆盖不变性实验，再测 wall/RSS。多仓产品版本必须逐组件绑定实际 SHA，不能套用一个 product commit。
