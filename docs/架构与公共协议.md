更新：2026-10-21。实现状态以固定分支代码和项目现状文档为准。下面带更早日期的协议记录是当时实现/验收历史；与本节冲突时，以本节 Issue #40 当前策略为准。

## 2026-10-21 Issue #40 自动研判运行协议

仅对用户明确批准源码外发、且授权、Provider/实现版本、固定报告 SHA、候选清单均能再次核验的智能审计启用自动研判。普通智能任务对固定扫描范围内所有满足静态证据路由条件的候选持久排队；不按任务累计 Token、模型请求数、运行时间、候选 5/100 条或美元估值截断。授权披露仍需说明按 Provider 实际用量计费，OHScanner 不提供 Provider 账单硬上限。Provider 的单次响应输出/context 协议上限、逐请求超时、用户取消、并发/固定源码范围和工具读取约束仍适用。

单次工具输出上限为 24 KiB。大响应在入模/落盘前丢弃内容，只反馈 `tool_result_too_large`、尺寸/hash 与缩小源码范围或符号的建议；不同的窄化查询可继续。相同已超限查询只执行一次；如果模型重复该请求，当前候选任务以可见 limitation/unknown 收敛，不将超限内容当作证据。其他无法满足的单次请求边界也必须返回可见限制并保持 candidate/unknown，不能伪装成成功结论。

Worker 重启遗留的 authorized smart operation 若状态为 interrupted、无结果、未取消且仍绑定原报告/源码/任务授权，可通过 `POST /api/v1/operations/{id}/retry` 显式恢复。`GET /api/v1/operations/{id}` 和 `GET /api/v1/scans/{id}/triage` 提供 `retry_available`；风险/任务详情展示按钮。该动作新建 operation，不改写旧结果或事件；新 spec 记录 `retry_parent_operation_id`、`retry_root_operation_id`、`retry_attempt`，并保持原 source/report/consent SHA 与批次关系。界面须提示可能重新调用模型并产生费用。未知 Provider 请求结果不会自动重放。

本节不覆盖 Issue #41 的多阶段跨文件语义链、必经反证、历史修复/版本对照和完整报告闭环；#40 通过的 API/Worker/合成 Provider 回归只证明代码路径与持久化约束，不证明真实漏洞、模型准确率或产品动态可达性。

  REVIEW --> OPS[区间 / 版本矩阵 / 案例报告]

Web 与 CLI 共用 execution.py；不得各造扫描器。历史工具对照与生产 Detector 分开。

### 多根目录登记与路径身份

部署环境/JSON 中的 target_roots 是静态管理员白名单；面板添加的独立目录另存于工作台数据目录的 managed-source-roots.json，API 与各 Worker 按需重读。根目录记录包括稳定 root_id、别名、规范真实路径、校验时间、发现预算和注册时的设备号/inode。文件更新使用互斥锁、0600 临时文件与原子替换。

GET/POST/DELETE /api/v1/repositories/roots 仅用于本机设置页；仓库发现优先使用 root_id，旧 root_index 只保留兼容。服务端验证绝对路径、真实目录、权限、符号链接、数据目录隔离、重复/重叠授权和根目录身份。根目录失效时不再进入有效 allowlist；仓库移动不会改变旧记录的 repository_id，须重新登记新路径。历史任务由固定 Git 快照、哈希和报告绑定，不随目录管理变化。

## 当前实际契约

新第一方 Detector 结果已经输出 schema v2，逐诊断绑定 source_sha256；外部历史工具结果仍兼容读取 v1。v2 不重写历史 JSON、报告哈希、候选 ID 或复核记录。
主要类型在 src/ohscanner/contracts.py：
- ScanRequest：目标 repository、full commit、snapshot、profile、provenance。
- SourceUnit：规范相对路径、language、text、SHA-256、parse_status。
- ScanContext：排序/去重 SourceUnits 与 shared_facts。
- DetectorFinding：位置、rule/message、候选 CWE、EvidenceObligations；可选 consequence 仍是候选。
- DetectorRun：ID/version/status、analyzed_files/findings/limitations、可选 file_outcomes。
- Detector：ID/version、supported_languages/required_facts、detect(context, units)；精确签名读代码。

Registry 显式批准 factory，浏览器不能提供 Python 模块名或 Shell 命令。
当前 Catalog 登记 A 的七项 C++ 检测器、B IPC 与 ArkTS/JS、C Ark Runtime TypedArray 静态研究候选、D 的敏感数据到日志研究检测器，以及默认开启的已披露组件 CVE 窄范围源码签名检测器。C 默认关闭且需显式选择；其 0.6.2 adapter / 0.8.13 model 只接受绑定的仓库 commit、目标 blob 和 creator 依赖 blob，依赖文件还须 SHA-256 一致且 AST 完整，并按 owner/method/signature 产生候选。版本、目标或依赖不匹配时为 not_analyzed；partial/unsupported 范围维持 blocked/unknown，不代表安全。宏、类型、继承与产品构建仍未证明。C/D/NULL 及已披露 CVE 的命中都不直接升级为产品漏洞结论，仍须确认精确构建、可达入口和安全影响。敏感数据 D 仍仅在仓库扫描页显式选择后执行，自动规划默认排除；未知版本会 blocked。example 不参与安全扫描。实际 ID/版本/默认策略从 /api/v1/detectors 读取。

POST /api/v1/audit-plans 在受限只读子进程读取固定 Git/AST，生成 SourceManifest 与语言/事实资格计划；不执行规则或入队。scan API 省略 detector_ids 时自动选择；显式列表继续兼容，空列表拒绝。计划、版本、源与元数据摘要入任务 spec；Worker 重算一致才执行/发布，报告记录原计划与真实覆盖。预览哈希变化需刷新。planning/sources 为无 FastAPI/DB 依赖的纯服务，由 CLI/Worker 共用。
可选 finding identity 字段作为增量证据，旧 diagnostic ID 和旧报告保持原样；缺失身份不回填成已验证。

状态必须分离：
- Web task：queued/running/completed_with_limitations/failed/cancelled/timed_out/interrupted 等。
- Detector execution：completed/blocked/failed。
- 文件覆盖：complete/partial/not_analyzed/failed；parse 状态另记。
- 人工复核与漏洞证据等级：不由 task completed 决定。

经过来源/范围验证的局部候选及义务不会因整体 blocked 而消失。
无 file_outcomes 的 legacy blocked 自报覆盖最多为 partial，不能推成 complete。
来源至少绑定 repository/full commit/tree/snapshot/file/blob/source SHA、
detector ID/version/rule/scope/profile；缺什么就记录缺口。归档成员使用 archive path/blob/SHA 与 member path/SHA 双重绑定，成员路径是虚拟路径，不能伪装成 Git blob；面板查看时从固定 commit 重新读取归档并重验两级哈希。归档展开不落盘，限 8 MiB 压缩、16 MiB 展开、2000 成员、1 MiB/成员；超限、链接、非 UTF-8 和损坏成员保留为 coverage limitation，不视作安全。

## 证据门与边界

默认 candidate/unassessed；partial/failed/未执行是 unknown，不是 safe 或 miss。
确认/报告需要固定目标、真实入口/攻击者控制或权限边界、可达敏感操作、
必要触发条件及具体 CIA 影响，记录可复核证据和仍未知项。
满足证据门后应升级并交付 PoC、影响/修复/报告，不能永久停留在 candidate。

常规扫描 Worker 使用任务子进程与资源限制，不等于逐 Detector 沙箱。AUTH-01 动态 Harness 只允许走独立 Docker Worker；容器无网络、去 capabilities、只读根目录、限制资源。标准 WSL Docker CLI/Worker 当前不可用；2026-10-16 一次明确授权的 Windows 暂存桥接运行通过组件 Harness，但不能证明 WSL Worker 可重复运行，也不能确认产品漏洞。
超时不发布残缺候选包；缺失分析保持 unknown。
数据库中的报告 hash、报告内 Markdown hash 与固定 blob 清单防意外混用，
不保证主机/数据库被完全控制后的完整性。

## 扩展原则

新源码同步、区间/版本、Agent、验证模块复用同一任务/证据服务。
文件级 AST 缓存可用 blob+parser+配置；跨文件语义要绑定依赖/宏/编译配置。
2000 文件/32MiB 总源码/1MiB blob 是当前限制，不直接移除来冒充全系统覆盖。
扩容先 batch Git、分片/聚合与覆盖不变性实验，再测 wall/RSS。

## 本轮新增操作面与验收状态

workbench operations API 使用单独的 SQLite operation 表与迁移备份，范围包括显式仓库同步、固定双 SHA 区间、带时区的 committer-date 区间预览、无需案例的 branch/tag 双端点比较、版本矩阵、只读调查、验证任务、操作事件/取消/日志/结果 hash，以及案例 JSON/Markdown 报告。区间端点扫描与 operation 记录在同一事务创建；branch comparison 在入队时解析并保存完整 SHA；扫描仍只读本地固定对象。

运行时影响和漏洞确认仍是独立层。候选变化返回 added/persistent/disappeared/unknown 等观察关系，不推导漏洞引入或修复；版本矩阵 impact=unknown。候选聚类仅用于审查浏览，按固定快照、Detector 版本、规则、文件、符号、源码 SHA 聚合展示，原始候选身份和位置不变；聚类不代表共同根因。只读调查输出固定源码、义务、Git 历史和有限符号信息，不调用模型或 arbitrary shell。AUTH-01 组件触发不证明真实产品入口可达，confirmed/reportable 仍需人工审查与额外证据。

## 2026-10-19 智能安全审计与仓库视图协议

POST /api/v1/audit-plans 和 POST /api/v1/scans 接受 audit_mode：standard_review（默认）或 static_only。静态 plan_sha256 仍只描述固定源码、规则和执行预算；另一个 workflow_sha256 绑定静态计划哈希与审计模式。面板创建任务时同时传 expected_plan_sha256 和 expected_workflow_sha256，后端分别重算并拒绝过期值。已创建任务在 job spec 内保存模式和流程哈希，重试沿用原模式；无模式的历史任务按兼容路径展示。

standard_review 默认执行静态扫描；不勾选任务级自动研判授权时不自动外发。用户可在新建审计中明确选择至多 5 条 R1 候选，并选择 0–5 条条件 R2（R2 上限不得超过 R1）。R1 是单轮候选研判；R2 仅在已绑定 R1 完成、high/critical 且存在未解决固定源码义务时使用只读工具。调度器从扫描报告重新读取候选和源码绑定，要求每项义务均有复核记录；R1 输出只充当路由提示，不能作为 R2 证据。R2 原子入队同时校验授权、R1 结果 SHA 和固定报告；批次决策持久化以支持重启幂等。撤销授权会记录审计事件并取消尚未完成的绑定 Agent 操作。授权预览绑定 R2 候选名额、工具/源码披露、Provider、版本及单次请求限制。每个已授权调查不设平台累计 Token、费用、模型/工具调用次数或总时长上限；Provider 账户计费/额度适用。每个 Provider 请求仍受单次输出上限和 45 秒超时约束；短暂 429/5xx 最多按请求策略退避重试一次，明确额度/鉴权错误或不可恢复错误会结束任务并如实标记失败。取消、固定源码工具限制和连续三轮无新增源码证据的收敛保护仍有效。

GET `/scans/{key}/triage` 同时返回独立的 scan_progress 和 triage_progress，并只关联该 job 与当前 report_sha256。GET `/scans/{key}/risks` 按确定策略分层：来源绑定不一致为 unknown；有效的完整人工 R0 复核，或通过固定源码/报告/候选绑定校验的 AI 源码调查，均可把候选列入“高可信风险候选”。AI 路径要求结构化研判被接受、结论为 likely_true_positive、至少一个 source-reviewable 源码义务标为 evidence_found，且有报告源码清单内的文件/行号/引文；同一候选其他义务仍可 unresolved，详情照常列出。任一 source-level contrary finding、绑定不匹配、无可定位引文或 unsupported claim 均不提升。此宽松门槛只用于人工优先复核；引用存在和逐字匹配不代表语义支持。风险项区分 `severity`、`risk_tier`、`confidence_basis` 与漏洞状态；详情可返回 `ai_summary`、`ai_evidence`、`ai_review_operation_id` 和 `ai_review_result_sha256`。高可信始终保留 `candidate`，Agent 的结论不能写入确认状态；人工 refuted/likely_false_positive 仅降为低优先级线索，不表示安全。GET `/scans/{key}/coverage` 汇总解析、检测器和未认领范围。

Agent 操作结果的最新证据图 schema 为 `ohscanner-evidence-graph-0.2.0`（旧操作可能仍保存 0.1.0）。图节点记录候选、固定源码证据、只读工具记录、模型请求/响应摘要、结构化主张、证据义务和流程阶段；每个节点有 `record_sha256`，全图有 `graph_sha256`，固定范围绑定 repository/commit/tree/report/candidate/source SHA。跨文件追查新增固定清单内 C/C++ Tree-sitter 语法调用点工具，图中可引用调用点及其外围函数语法片段；这只证明固定提交存在语法调用表达式，不解析重载、虚函数/函数指针目标、可达性或执行。未调用该工具时跨文件追查明确为 `not_performed`；partial parse 或扫描受限时标记为部分结果。支持、反向与未决阶段只记录模型提交的结构化义务处置；源码读取或普通工具调用不证明已主动搜索反证，系统也不验证搜索是否穷尽。边只说明模型引用、步骤依赖或审计关联，不代表主张为真。官方公告、受影响版本和修复补丁尚未作为允许工具来源，因此该阶段标为 `not_available`，N-day/1-day 分类为 `unknown`。图和原结果均保持 candidate-only；当前仍不是可恢复的多角色 DAG，也无 A/B/C/D 冻结漏洞真值集。

POST `/scans/{key}/reports/snapshots` 将当时的双阶段状态、风险/覆盖、授权摘要、Agent operation/result SHA 和现有合规验证门写入 SQLite v7 的 `risk_snapshots`、`report_snapshots`。快照按内容摘要幂等；后续复核或研判状态变化会生成新版本，旧 JSON/Markdown SHA 和内容不变。原始静态报告保持独立。数据迁移先在线备份；不会在报告里复制 Provider 密钥。`validated_vulnerability` 只沿用案例人工评估与通过运行时可达性门的既有路径，风险层级本身不写入确认状态。

仓库视图分为三种：GET /api/v1/repositories/list 供普通导航和表单，仅返回 id/name；GET /api/v1/repositories/managed 供本机设置页显示登记路径；GET /api/v1/repositories/roots 供本机设置页显示可信根路径、别名、可用状态和仓库计数。GET /api/v1/health 只返回 target_root_count，不再枚举绝对路径。旧 /repositories 路由暂保留以兼容本地客户端，新的普通页面不得用它展示路径。

条件 R2 状态由操作 schema v8 保存，迁移前在线备份。GET /scans/{key}/triage 的每个 batch 包含 conditional_r2.state、操作 ID、逐候选决定清单、决定摘要及安全错误码/原因；R1 未终态期间显示 in_progress。R2 状态包括 awaiting_r1、queued、candidate_limit_reached、not_needed、failed_selection 与授权变化阻断。candidate_limit_reached 表示符合条件的候选数超过用户预览并授权的 R2 名额；名额内任务可已排队，未入选候选不会自动研判。该状态与 Provider 额度、Token 或费用无关。结果不会把候选升级为漏洞；validated_vulnerability 仍由既有独立人工/运行时证据门决定。旧记录中的 budget_limited 在读取时映射为 candidate_limit_reached。

操作 schema v9 在 v8 基础上增加 `triage_cancellations`，记录任务级停止智能研判或整项审计取消的持久标记，并在迁移前生成在线备份。`POST /api/v1/scans/{key}/triage/cancel` 只停止该扫描任务绑定的 R1/R2 研判：扫描状态、静态报告和任务级外发授权保留；尚未开始的 Agent 操作取消，运行中的操作收到取消请求。`POST /api/v1/scans/{key}/cancel` 取消整项审计，并同时写入研判取消标记，防止扫描结束或 Worker 重启后再自动排入 R1/R2。R1 批次创建在同一写事务重新检查标记，避免取消与调度并发时出现迟到的任务。该标记只约束关联审计，不取消其他任务。

`GET /api/v1/overview/risks?scan_limit=10` 提供首页最近审计风险摘要，最多读取 20 份报告，汇总 candidate、待验证、未评估和独立人工确认计数，并给出至多 12 条相对路径候选定位。聚合候选数是报告观察数，可能跨报告重复，不能解读为唯一漏洞数；绝对本机仓库路径不会从该接口返回。首页显示 Provider 是否已配置，不推断连通性；任何源码外发仍需逐任务授权。

### 2026-10-21 智能调查累计预算策略

任务预览和授权 manifest 不绑定平台累计 Token、费用、模型调用次数或总墙钟时限。用户授权的是候选范围、固定来源、Provider 目的地与模式；R2 候选名额仍受预览中的数量约束，但该限制仅决定哪些候选可以入队，不是模型预算。Agent 每次请求继续受 Provider 单次输出上限和 45 秒请求超时约束；读取工具保留单次时间、字节和固定提交范围限制，用户可取消，连续三轮无新增源码证据时收束。短暂 429/5xx 最多按现有策略退避重试一次；明确 Provider 额度耗尽、鉴权拒绝、不可恢复错误及取消会以失败/取消结束，不标记为完成。实际账单与余额以服务商账户为准，OHScanner 不承诺绕过服务商额度。费用估算仅是回顾性展示，不作为授权门槛。

旧客户端提交的 max_cost_usd 及旧任务累计预算字段不构成当前智能调查的执行门槛；新创建的 Agent 授权不写入任务级累计费用上限。静态扫描自身的 CPU、内存和单次扫描超时仍按扫描执行计划约束。


## 2026-10-21 候选报告与 PoC 测试草稿

获授权的 tool_agent 调查可在固定源码分诊和反证阶段后额外发起一次结构化草案请求；该阶段写入调用计数与用量统计，调用仍绑定同一任务的仓库、commit、报告、候选、Provider、提示版本、工作流及源授权。单次 Provider 输出上限和请求超时有效；平台不设置调查累计 Token/费用上限。

模型返回根级 vulnerability_report 与 poc_draft，服务端保存为 result.agent_assessment 同名字段；案例报告 API 映射至 operation.agent_triage 同名字段，并附 artifact_generation 状态。每条引文须引用本次已读取的固定源码证据 ID、文件和有效行范围，且文件必须属于报告 source_inventory 与审计 include scope；服务端从固定证据重建引文文本并补充 source SHA/blob。任意引用无效则整份草案降级为 insufficient_evidence。

报告标记 draft_unverified；PoC 只能是本地、非破坏性、未执行的测试草稿，状态 draft_unexecuted。没有 likely_true_positive 且带源码引用的主张时，PoC 强制为 insufficient_evidence 且代码为空；常见命令执行、网络和写文件模式会按保守词法规则拒绝。该词法检查不是语义安全证明。草案不会执行或应用，也不改变候选状态与 validated_vulnerability=0；语法、模型输出或草案都不构成漏洞确认。

platform_enforced=true 表示 OHScanner 会按此费率卡门槛约束任务级自动批次，不代表对 Provider 实际账单设立硬上限。结算地区/币种、失败请求费用和供应商侧价格变化不由工作台控制；明细仍须对照真实账单。静态扫描和单候选独立授权不因缺少任务级上限而受阻。离线测试使用固定费率卡，不执行真实 Provider 请求。

## 2026-10-21 OpenHarmony 在线仓库目录与固定版本导入（Issue #39）

`GET /api/v1/repositories/official-catalog?q=&page=&per_page=&refresh=` 读取 GitCode `openharmony` 公开代码仓库目录，服务端按 GitCode `namespace.path`、public/code 字段筛选并在本机持久化 5 分钟目录缓存。响应携带目录摘要、更新时间、GitCode API 来源、过期状态和身份限制说明。该 API 列表元数据不能独立证明官方身份或仓库内容可信；不得据此确认漏洞。

`POST /api/v1/repositories/official-catalog/preview` 只接受仓库 slug，后端从当前公开目录取得默认分支，查询该分支的完整 Commit SHA 和目录项预览，并返回绑定摘要。Commit 固定后不能以分支名替代。目录项来自 GitCode API、尚未独立验证；完整根 Tree SHA 仅在 Worker 取得固定 Git 对象后由 `git rev-parse <commit>^{tree}` 本地核验。

`POST /api/v1/operations/repository-import-scans` 提交 slug、预览分支、完整 Commit、摘要与静态扫描范围；服务端重查默认分支和预览摘要，变化则拒绝。持久化 `repository_import_scan` operation 仅固定 GitCode HTTPS URL；Worker 禁止 credential helper、系统/全局 Git 配置、HTTP redirect、file/ext protocol、checkout/hooks 与 submodule fetch，并拒绝含 gitlink 的仓库。默认使用浅层单分支对象克隆；克隆完成须再次验证 Commit，再本地绑定 Tree 并原子登记仓库和排入静态扫描。相同仓库的下载由每仓库文件锁序列化；相同固定版本命中缓存时不联网，其他 Commit 使用不同缓存目录。队列任务可持久化查询；扫描候选仍保持 candidate。

缓存根由 `repository_cache.roots` 或 `OHSCANNER_REPOSITORY_CACHE_ROOTS` 配置，空间边界为 `max_bytes`（0 表示未配置总量上限）和 `minimum_free_bytes`。仅允许绝对、非符号链接根目录；创建和使用路径前检查根、组织目录、仓库目录与目标是否越界/被替换。下载前检查磁盘保留空间与 API 提供的目录大小估计（若缺失则不据此推算），下载过程中轮询缓存字节数及磁盘余量并在触及上限时终止 Git 进程组，下载后再次检查大小和余量；失败时清除本 operation 创建的临时目录。进程被强杀可能留下临时目录；同仓库下次导入持锁后只清理其精确 Commit 前缀的受控临时目录。该静态网络读取仍依赖 GitCode API 和 Git 服务可用性，没有独立镜像签名或官方身份认证。

旧 `POST /api/v1/operations/source-sync` 保留原有显式同步、返回远端 refs 且不检出/不扫描的语义；增加禁止 Git redirect 与 submodule recurse 的参数，不把它自动等同于新的一键静态导入。

### 2026-10-21 案例报告的固定源码、建议草案与验证计划

`GET /api/v1/cases/{case_id}/report.json` 将案例报告 `schema_version` 提升为 2，候选条目增加 `source_anchor`、`remediation_draft` 与 `poc_plan`。源码锚点绑定当前 job 的 commit、report SHA、仓库相对路径、候选行、Git blob（如适用）和源码 SHA-256；报告重新从固定 Git 对象读取文件并核对来源。源码不可取、报告/提交不一致、候选无来源哈希或行号越界时锚点为 `unknown`，修复草案没有正文，安全验证计划没有步骤。

当前修复正文是按受支持 CWE 输出的确定性通用模板，状态为 `draft_unverified`，不是 AI 归纳的已验证根因，也不是实际补丁；CWE/规则元数据本身不证明该位置存在漏洞。没有适用模板或来源锚点时，草案为 `unknown`。Agent 摘要和下一步建议只在操作绑定完全匹配、引用完整、引用文件/行/原文能再次从固定提交源码验证后显示；界面和导出仍标为未验证。引用原文存在不等于模型结论语义正确，也没有建立 AI 引文与修复草案之间的因果映射。引文缺失、来源不匹配或文件不在本任务扫描清单时，模型摘要/建议隐藏并保持 `unknown/candidate`。

`poc_plan.state=plan_only` 只描述供人工审查的验证计划，所有步骤都引用同一候选源码锚点；`execution.requested/queued/executed` 初始均为 false，不自动创建或运行 Harness/PoC。计划不预设期望结果，须由人工按接口契约或受审查控制定义 oracle。确认执行需另走既有的授权与隔离验证队列。组件 Harness 输出不等于产品可达性、真实利用或漏洞确认，`validated_vulnerability` 不由这些字段改变。
